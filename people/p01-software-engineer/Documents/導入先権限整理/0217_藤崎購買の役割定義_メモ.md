# 藤崎の役割をまとめる下書き

山本さんとの次の確認用。設計資料の7役割を5つにできるか。人数の話ではない。

| 現在の役割 | まとめた後の案 | 理由・残す操作 |
|---|---|---|
| 発注申請入力 | 申請担当 | 同じ担当が申請を入れ、戻った申請を直す一連の作業 |
| 差戻し訂正 | 申請担当 | 申請入力と同じ担当の続きの作業 |
| 発注照会 | 購買閲覧者 | 同じ担当が発注と納品を続けて照会する |
| 納品照会 | 購買閲覧者 | 発注照会から続く確認 |
| 購買承認 | 購買承認者 | 申請を承認または差戻しする仕事として残す |
| 検収記録 | 検収担当 | 検収の記録として残す |
| 利用者管理 | 権限管理者 | 利用者の管理として残す |

## 分けて聞く

- 承認のとき、担当に回った申請の何を見られれば判断できるか。個別申請の明細として確認する。
- 未着などを調べるための発注・納品一覧は、誰がどの範囲を見るか。承認時の明細とは別欄で確認する。
- 検収記録と今の紙の回付はどうつながるか。役割をまとめる話だけで紙をやめると決めない。

まだ対応案。担当者への割当てや切替えは決めていない。
