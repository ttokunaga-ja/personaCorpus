# Application Desk R7: change explanation

Document: ABS-2026-EX-001  
Version: 0.2  
Date: 13 May 2026  
Prepared by: Miyu Tanaka  
For: Laura Nichols, editorial review  
Status: Draft; provisional audience placement for discussion on 19 May; publication decision pending

## Scope and intended readers

This draft retains sixteen topics in one booklet for review. Ten concern actions or checks by reception staff; six describe information an administrator may need to investigate an enquiry. The audience column is a provisional proposal, not a decision to split the material. Please check the boundary with us on 19 May.

The explanations cover current checks and proposed changes. A proposed improvement is not evidence that the R7 screen behaves as described. Neither this draft nor its language review decides the reception method or publication.

## Changes and user actions

| Point | Provisional audience | Explanation |
|---|---|---|
| U01 Receipt and completion | Reception | A receipt number indicates that the application has been received. It does not mean the business process is complete; check the processing status separately. |
| U02 Before resending | Reception | Use the receipt number to check the saved result before considering another submission. If the result cannot be established, raise an enquiry rather than assuming that resending is safe. |
| U03 Destination on a proxy application | Reception | Before confirming an application on another person's behalf, review the destination displayed. If it looks wrong, seek clarification. This check does not ask the reader to change routing settings. The proposed improvement needs verification. |
| U04 Replacement attachment | Reception | After selecting a replacement, check the displayed file name before confirming. Whether the proposed display updates as intended remains to be verified. |
| U05 Returning to input | Reception | If a correction is needed on the confirmation screen, use the guidance to return to the entry and check it again. The proposed guidance is under review. |
| U06 Required fields | Reception | Read the required-field guidance and complete missing information before proceeding. The proposed guidance is under review. |
| U07 Long receipt numbers | Reception | Compare the complete receipt number when identifying a submission; do not omit characters. The proposed presentation is under review. |
| U08 List and details | Reception | Select the application in the list, inspect its detail and return to the list to continue. The proposed return behaviour is under review. |
| U09 Two statuses | Reception | Read the receipt status in the list separately from the processing status in the detail. Receipt does not establish completion of the subsequent work. |
| U10 Printed heading | Reception | Identify the application using its detail rather than the printed heading alone. A change to the heading remains a candidate. |
| A01 Duplicate receipt enquiry | Administrator | Compare the available records for potentially duplicate receipts. The matching key has not been settled; the reception reader is not asked to investigate logs. |
| A02 Destination and routing | Administrator | For an enquiry about a proxy application, compare the destination shown to the applicant with the internal routing destination available to the investigation team. This does not decide a routing configuration. |
| A03 Attachment history | Administrator | When investigating a replacement enquiry, distinguish the currently displayed file name from the replacement history. The current display alone does not establish the history. |
| A04 Performance context | Administrator | Identify the version, concurrent usage and sample when describing a performance result. No result or guarantee is established here. |
| A05 Receipt records | Administrator | Check which receipt records are available for reconstructing an enquiry. Their scope and retention period remain unsettled. |
| A06 Incident handoff | Administrator | Pass the receipt number, the observed situation and the time of occurrence to the investigation contact. |

## Open questions and review status

Laura, I have accepted “received” in place of “completed” and changed the proxy instruction to “review the destination”. I have removed the instruction for the reception reader to check the log. Please look at whether the proposed audience column makes the responsibility boundary clear. In particular, the user's review of a displayed destination and the administrator's comparison with internal routing are separate actions.

All sixteen points remain together while we prepare for the 19 May discussion. The proposed improvements in U03–U08 and the printed heading in U10 still need behaviour checks. Reader placement, the reception method and publication remain open.
