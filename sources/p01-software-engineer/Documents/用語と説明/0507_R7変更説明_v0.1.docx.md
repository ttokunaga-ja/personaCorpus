# Application Desk R7: change explanation

Document: ABS-2026-EX-001  
Version: 0.1

Prepared by: Miyu Tanaka  
For: Laura Nichols, editorial review  
Status: Draft; review pending; publication decision pending

## Scope and intended readers

This draft gathers sixteen explanation topics in one candidate user notice. It is intended to help readers understand application submission, checking a result and responding to an enquiry. The topics include operational investigation as well as actions at the screen; the intended reader for each needs review. These descriptions do not establish that proposed changes have been implemented or approved for publication.

## Changes and user actions

**U01 — Receipt and completion.** Your application is completed when a receipt number appears. Keep the number for later enquiries. The intention is to explain the state after submission.

**U02 — Before resending.** Look for the receipt number before sending the same application again. Use the number to check the existing submission before deciding what to do next.

**U03 — Destination for an application made on someone's behalf.** Change the routing before you submit. Check the destination for the application before confirming it.

**U04 — Replacement attachment.** When an attachment is replaced, check the displayed file name before confirming the application. The proposed improvement is still to be verified.

**U05 — Returning to input.** If a correction is needed on the confirmation screen, follow the guidance to return to the input screen. The proposed guidance is under review.

**U06 — Required fields.** Use the required-field guidance to find and complete missing information. The proposed guidance is under review.

**U07 — Long receipt numbers.** Compare the whole receipt number without omitting any characters. The proposed presentation is under review.

**U08 — List and details.** Open the relevant application from the list to view its details, and use the return route to go back to the list. The proposed return behaviour is under review.

**U09 — Status.** Distinguish the receipt status shown in the list from the processing status shown in the details. A receipt indicates acceptance of the application, while the processing status describes the subsequent work.

**U10 — Identifying a printed application.** Do not rely on the printed heading alone to identify an application; check the details. A change to the printed heading remains a candidate.

**A01 — Duplicate receipt investigation.** Check the log before sending the application again. Compare the information used to identify potentially duplicate receipts; the matching key is not yet settled.

**A02 — Destination and internal routing.** Compare the destination displayed for the application with the internal routing destination when investigating an enquiry. This explanation does not decide a new routing configuration.

**A03 — Attachment history.** Distinguish the currently displayed attachment name from the replacement history when investigating an attachment enquiry.

**A04 — Performance context.** When describing performance, identify the version, number of simultaneous users and sample used. No result or guarantee is established here.

**A05 — Record coverage.** Check which receipt records are available for reconstructing an enquiry. The retention period is not settled.

**A06 — Incident handoff.** Pass the receipt number, the situation and the time of occurrence to the investigation contact when reporting an incident.
