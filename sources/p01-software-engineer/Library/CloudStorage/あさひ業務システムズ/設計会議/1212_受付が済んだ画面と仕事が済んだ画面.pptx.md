## スライド2

レイアウト：図

題：利用者が画面を移る順

図の内容：

入力 → 送信前に内容を確認 → 送信 → 受付結果で受付番号を控える → 受付一覧で同じ申請を選ぶ → 申請詳細で処理状況を見る。

送信後に結果を表示できない場合は、受付結果からではなく「結果不明」から受付一覧へ進み、送った申請を探す分岐を示す。一覧で確認できない場合は送信時刻と申請の種類を控えて窓口へ問い合わせる。結果が見えないことだけで受領の有無や再送を決めない。

発表者メモ：まず結果が見えて番号を控える流れをたどり、次に結果不明から一覧を確認する流れを示す。確認担当が後者を先に試す場合も、この分岐から始めてもらう。

## スライド3

レイアウト：2段

題：受付と業務処理は別の段階

上段「受付」：受付番号 SD-241126-018 は受け取った配送便変更を探す控え。一覧の Receipt status は Received。受領を示し、担当部門の仕事が終わったことは示さない。

下段「業務処理」：同じ申請を詳細で開くと Processing status は In review。担当部門の確認は進行中。実際に処理が終わったときの値 Processing completed はそのまま使う。

発表者メモ：一覧に処理状況はない。Received を見たら詳細へ進み、別欄の In review を読む。番号と受領日 2024-11-26 は業務の終了日を表さない。
