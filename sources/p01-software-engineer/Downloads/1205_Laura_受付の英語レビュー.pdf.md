# Application Desk: receipt wording review

Report: HES-2024-ER-001  
Version: v1.0  
Date: 5 December 2024  
Author: Laura Nichols, Harlow Editorial Services  
For: Miyu Tanaka, Asahi Business Systems

## Scope and finding

I reviewed ABS-2024-EX-001 v0.1, the 64 English labels and messages in the six applicant-facing screen contexts. The concern below is not the word “complete” wherever it appears: it is the use of completion language for receipt, before the responsible department has necessarily finished its work. The suggested wording is for discussion on 9 December; it is not an instruction to change the live service.

Miyu confirmed on 4 December that the number identifies a received application, that progress is checked in the details, and that a user who cannot see a result should first check the list. The wording should help a reader follow that route without assuming more than the screen establishes.

## Eight positions for discussion

| No. | Position | Current English | Recommended English |
|---|---|---|---|
| 23 | Receipt result heading | Application complete | Application received |
| 24 | Receipt result message | Your request has been processed. | We have received your application. |
| 25 | Receipt result number label | Completion number | Receipt number |
| 26 | Receipt result button | View completed application | View application details |
| 39 | Application list column | Completion status | Receipt status |
| 40 | Application list value | Completed | Received |
| 53 | Details receipt date label | Completed on | Received on |
| 54 | Details receipt value | Done | Received |

## How a reader may act

On the result screen, “Application complete” and “processed” can make the number look like evidence that the requested work has ended. A reader might keep the completion number as a certificate and tell a colleague the delivery change is finished. “Receipt number” instead identifies the application for a later inquiry; the number does not answer whether the department has acted.

In the list, “Completion status: Completed” can be read as the outcome of the department's work. A reader may stop at that row and not open the details or check with the responsible department. Naming the column “Receipt status” and its value “Received” makes the scope of that status visible; the details remain the place to read processing progress.

In details, “Completed on” and “Done” can appear alongside “Processing status: In review”. A reader may see contradictory states and ask which one is correct. “Received on” and “Received” identify the receipt stage, leaving “In review” to describe the separate processing stage. When the department's work really has finished, “Processing completed” is appropriately specific and need not be replaced merely because it contains “completed”.

## Points for 9 December

Please walk through the same delivery schedule change from the result screen to the list and then details. Before showing the details, ask what the list row alone suggests. Check whether each proposed label tells the reader what happened and where to go next, particularly whether the button can open a request still in progress.

“Submitted” describes the sender's action and does not confirm receipt. “Accepted” may imply approval. “Successfully completed” still leaves the object of completion unclear. I recommend discussing these alternatives against the receipt screen rather than adopting one as a blanket replacement.

For the other contexts, please check the submit button as an action yet to occur and the unavailable-result message as an inability to display the result, not as proof of receipt. If the result is missing, the list is the first check before deciding whether to send again. Please confirm both the wording and its position; the review does not establish a release date or a change in the user's environment.
