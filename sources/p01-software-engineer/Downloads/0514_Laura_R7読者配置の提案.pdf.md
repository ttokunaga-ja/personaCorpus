# Application Desk R7: proposed placement by reader

Report: HES-2026-ER-002  
Version: 1.0  
Date: 14 May 2026  
Prepared by: Laura Nichols, Harlow Editorial Services  
For: Miyu Tanaka, Asahi Business Systems  
Reviewed document: ABS-2026-EX-001 v0.2, shared 13 May 2026

## Recommendation

Miyu, the revised wording is clearer about what the reception reader should do. I recommend separating the sixteen points into ten for reception staff and six for administrators who investigate enquiries. The distinction is between a person checking information presented during an application and a person comparing that information with internal records or routing. The six points should retain a home in an administrator explanation; removing them from the reception text alone would leave the investigation context unstated.

This is a placement proposal for the 19 May discussion, not an agreed split. The proposed changes in the draft still require a behaviour check, and neither this review nor the proposed placement establishes a publication decision.

## Where the draft crosses a reader boundary

The following short extracts are from EX-001 v0.2. They are paired because proximity in one booklet can make two different responsibilities appear to be a single instruction.

| Reception action in v0.2 | Investigation context in v0.2 | Editorial concern |
|---|---|---|
| U03: “review the destination displayed” before confirming a proxy application. | A02: “compare the destination shown to the applicant with the internal routing destination” available to the investigation team. | The first reader checks what is displayed and seeks clarification if it looks wrong. The second compares it with internal routing. If the two instructions run together, a reader could infer that checking the destination requires changing routing settings. Neither sentence should be presented as an instruction to change configuration. |
| U04: “check the displayed file name before confirming.” | A03: “distinguish the currently displayed file name from the replacement history.” | The visible name is useful before confirmation, but it does not establish the replacement history. A reception reader should not be asked to reconstruct that history in order to check the name. |
| U02: “check the saved result before considering another submission.” | A01: “Compare the available records for potentially duplicate receipts.” | Checking a result using a receipt number and investigating possible duplicates are different tasks. The matching key is unsettled; do not turn it into a log-checking instruction for reception staff. |

A05 asks the investigator to “Check which receipt records are available for reconstructing an enquiry” and says that their scope and retention period remain unsettled. Beside the reception instructions, this could be read as a request for the user to configure the history or retention scope before checking a result. That is a possible reading of the combined presentation, not an instruction the draft explicitly gives. Please place the availability and scope question with the investigation material and avoid implying that the user can or must set it. The same distinction applies to A03: checking a displayed name must not imply that the user sets or inspects the history.

## Proposed allocation

| Reader and purpose | Points | Reason for placement |
|---|---|---|
| Reception staff: checks and actions around an application | U01–U10 | Receipt versus completion; result before resending; displayed destination; displayed attachment name; return to input; required fields; complete receipt number; list and detail navigation; separate statuses; identification without relying on the printed heading. These are the checks or guidance the reception reader needs in the ordinary flow. |
| Administrator or investigation contact: enquiry and handoff | A01–A06 | Duplicate-record comparison; displayed destination versus internal routing; attachment history; performance context; available receipt records; incident handoff. These explain how to investigate or pass an enquiry on, without changing the reception reader's actions. |

The count is ten and six, with all sixteen retained. A01's matching key, A04's performance result and A05's record scope and retention period remain open; placement does not settle them. Nor does it grant permissions, change settings or promise performance. U03–U08 and the proposed printed heading in U10 still need verification, so the reception text should continue to distinguish existing checks from proposed improvements.

## Questions for 19 May

1. **Kazunori Takahashi — reception responsibilities:** Is checking the displayed destination, file name and saved result within the reception staff's normal work? When the destination looks wrong or the result cannot be established, whom should they ask instead of changing a setting or investigating records themselves?
2. **Norimi Watanabe — investigation responsibilities:** Who compares the displayed destination with internal routing, and who can establish which receipt records and attachment history are available? Please identify the boundary of the investigation team's responsibility before we describe it as an instruction. The matching key and record scope should remain open until confirmed.
3. **Both:** If the six investigation points are moved, will the person receiving an enquiry still have enough context to connect the user's receipt number, observed situation and time of occurrence with the investigation? Which details belong in the reception explanation as a handoff, and which belong in the administrator material?

Please use the meeting to test the allocation against the work each reader actually performs. I can then review the English for the agreed boundary. Screen behaviour and publication remain for the responsible team to confirm separately.
