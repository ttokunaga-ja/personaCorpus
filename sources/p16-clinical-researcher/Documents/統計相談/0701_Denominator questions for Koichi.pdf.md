# Questions for Koichi: recordability and denominators
Document: KRC-LDO-20240628-QRY-001　Version: v1.0
Drafted: 2024-06-28　Author: Mitsuko Suzuki
To: Koichi Goto, Yoshimura Statistics LLC

## Background
The low-dose observational study plans 48 participants. Its purpose is to see whether the planned items can be recorded and where recording stops; it is not designed to establish an effect. An earlier table displayed a recorded zero, an unrecorded value within scope, and a blank outside scope as the same zero. That display cannot recover the item denominator or the reason for absence.

Please read the 14 June denominator table from the item definition and unit to the target count, recorded count and missing-reason rows. The cells are intentionally unfilled. Visit, dose category and number of additions are counted by participant; the proposed unit for query response date is the issued query row. We would welcome your advice on the following points before the discussion.

## Questions
1. **Population:** Is it clear that 48 is the planned study size, rather than an observed count or a fixed denominator for every item?
2. **Observation unit:** How should we state the distinction between participants and issued query rows so they are not added together?
3. **Item eligibility:** Should eligibility for each item be determined before looking at whether a value was recorded?
4. **Denominator:** Is the number meeting the item's eligibility condition an appropriate denominator? For query response date, should all issued query rows be included, including those awaiting a response?
5. **Recorded:** Is an item recorded when its value or date is present in the source record, with the count reported separately from missing values?
6. **Entered zero:** May a zero entered after checking that no additions occurred be retained as a recorded value, rather than treated as missing?
7. **Missing reason:** Can missing values within scope be shown by reason, such as not performed and source record unavailable, without converting them to zero?
8. **Reason unresolved:** How should an unresolved reason be displayed while the query is open, and what footnote would be appropriate if it remains unresolved at reporting?
9. **Outside scope:** Should items outside the eligibility condition be excluded from both the item denominator and missing counts?
10. **Correction after query:** How should we retain the original record and correction history while reassessing the classification after a response?
11. **Table check:** Is it appropriate to check within each item that the target count equals the recorded count plus the sum of missing counts by reason, without summing across items?
12. **Reporting limits:** How should we describe the limits of these counts so that recordability is not interpreted as evidence of an effect?
