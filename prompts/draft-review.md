# 原稿の中身を制作とは別の実行でレビューする

指示の「読むファイル」に示されたパスを用途に従って開いてください。資料の本文は指示に埋め込まれていません。事実の台帳は、対象の行（計画前は依頼）に関係する案件・出来事の見出しを検索し、該当する部分を読んでください。
AGENTS.md、SPEC.md、runbooks/PRODUCTION.md の「原稿」、runbooks/REVIEW.md の「原稿のレビュー」、persona 定義、計画、事実の台帳を読んでください。BATCH_CONTEXT の rows に対応する `sources/<persona>/<計画のパス>.md` を 1 件ずつ全文読み、関連する過去の原稿と照らします。制作側のログ・最終出力・言い訳は読みません。成果物の見た目はこの段階の判定対象ではありません。

runbooks/REVIEW.md の原稿の 10 観点をすべて適用し、1 つでも当てはまれば reject にします。

1. 固有の内容：計画の出来事・数値・結論が本文にあり、一般論や決まり文句で埋めていないか。
2. 差し替えの量産：同じ batch や既存の原稿と骨組みが同じで、名前・日付・数値だけが違わないか。同じ文書の版違い（下書きと修正版、入力前と入力後の出力）は、計画に関係が書かれ、違いに意味があれば量産ではありません。
3. 実務：その職種で使える内容か。調整表の差異、議事録の決定と担当、提案の金額と条件、契約の当事者と条項などがあるか。 判断の根拠を示す表では、挙げられた資料を開き、その行の時刻・件数・結論をどこまで裏づけるかを確かめます。別の記録から得た値を同じ行に載せるときは、その出典もたどれるかを確認してください。
4. 設定：人物・役職・組織・案件・日付・金額・経緯を、定義・台帳・関連原稿と照合する。定義にない組織や案件、返信が元メールより前になるなどの矛盾はないか。
5. 数値：合計、本文と表、グラフと表、関連文書を計算・照合する。数式の範囲は正しく、未確認項目を 0 として合計していないか。
6. 厚み：その種類として短すぎないか。短いのが自然なメモやメールは除く。
7. 書き手：誰が誰に向けて書いたか、言葉づかい・立場・関係が分かり、メールの宛先と用件が合うか。
8. 名前と場所：persona の整理の癖に合い、人が付ける名前か。名前が示す内容と一致するか。
9. 制作の痕跡：本文に合成の注記、制作用 ID、検査や評価の記述、サンプル・ダミー・テスト用などの断り書き、仮の文がないか。原稿の先頭設定は本文と区別する。
10. 成形できるか：指定の型の管理欄・表紙に必須の項目を一覧と実物で調べ、当該文書自身の番号・版などの値が原稿にあるか照合する。引用元の番号しかない場合も不足としてD10に記す。型が文書の状態を求める場合は、表題下の該当欄を読み、文書種別だけで終わっていたらD10とする。派生版が引き継ぐ欄も元原稿で確認する。表の行、図の数値、写真の対象と読める文字など、形にする中身が全部あるか。先頭の path・kind・author・derived_from が計画と対応し、派生元と違いが分かるか。

再レビューでは、まず BATCH_CONTEXT の reasons と previous_verdicts を読み、前回の不合格理由が解消されたかを実物で確認します。前回 pass だった行が前回と同じ状態なら、新しい理由で reject にしません。

判定は pass または reject だけです。reject は、該当する観点と問題の具体的な箇所を確認できた場合だけにします。抽象的な懸念や好みだけで reject にしません。具体的な問題が確認でき、「直せば使える」状態なら reject です。自動検査の通過や件数を合格理由にしません。合格にも具体的に何を確かめたかを 1 文で書きます。不合格はどの観点のどの箇所かを示します。

BATCH_CONTEXT の review_output に、ヘッダなし TSV（計画の相対パス、pass/reject、観点、理由）の 4 列で、対象の全行を 1 件 1 行ずつ書いてください。原稿のパスではなく、people/<persona>/ からの相対パスを使います。観点は不合格なら `D1`〜`D10` の該当する番号、該当がなければ `other`、合格なら空にします。理由にタブ・改行を含めません。

最終出力には、batch 全体の所見として、完成版ばかりで下書き・古い版・途中のメモ・うまくいかなかった記録がなく整いすぎていないか、依頼の重点を原稿全体でたどれるかを書きます。

Message-ID が台帳・計画の値と一致していれば、その形（人が読める語が入っているなど）を理由に破棄にしません。

レビューは読み取り専用です。書いてよいのは 指定された review_output と BATCH_CONTEXT の work 以下のレビュー用の一時物だけです。原稿、成果物、計画、台帳、型、persona、資料を変更せず、修正も削除もしません。stage・commit・push はしません。

実行専用の作業フォルダは BATCH_CONTEXT の work、レンダリング先は render です。他の実行の作業フォルダへ一時物を書きません。指定された review_output だけは指定先へ書きます。
