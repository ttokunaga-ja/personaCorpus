# 合格した原稿を1件ずつ成形する

指示の「読むファイル」に示されたパスを用途に従って開いてください。資料の本文は指示に埋め込まれていません。事実の台帳は、対象の行（計画前は依頼）に関係する案件・出来事の見出しを検索し、該当する部分を読んでください。
AGENTS.md、SPEC.md、runbooks/PRODUCTION.md、runbooks/REVIEW.md の「見た目のレビュー」、persona 定義、計画、テンプレート一覧と実際の型を読んでください。成形するのは BATCH_CONTEXT の rows だけです。各行の `sources/<persona>/<計画のパス>.md` を全文読み、合格したその原稿の内容だけを、計画のパスの `people/<persona>/` 以下に成形します。

原稿は中身の正本です。文章、数値、表、数式、図の情報、メールのヘッダ・本文・引用・添付、スライドのメモ、変更履歴とコメントを欠落・変更・追加しません。先頭設定は成果物の本文に写しません。内容に問題や不足があれば原稿を直さず、その行の理由を報告して残りを進めます。

- **型**：Office は `templates/<persona>/` の実際の型を開いて内容を入れます。自社の文書は自社の型、社外から届いた文書は相手の型にします。個人のメモなど型なしが自然な場合は計画に従います。空の欄や仮の内容を残しません。型には中身の入っていない書式つきの行や仮の合計欄を残しません。明細と合計の行は、型の README.md に書かれた決まりに従い、文書の実際の行数に合わせて成形のときに書式ごと作ります。
- **表**：原稿のシート・行・数式・注記を再現します。合計や差異の数式を値に置き換えず、正しい計算結果も保存します。数式を含む XLSX は、成形のあと stamp の前に進行役が `bin/recalc` で再計算し、計算結果を保存します。成形の中でも `bin/recalc` と `bin/render` で結果を確かめてよいです。数十行以上の明細は原稿の定義・行の作り方・合計条件・代表行に従って展開し、独自の事実を加えません。原稿に書かれた代表の行は、書かれた値のまま必ず含めます（残りの行をその前後に展開します）。展開したあと、行数と合計が原稿の条件に合うことを確かめます。
- **対象の行は全部作る**。重い行（数式の多い XLSX、図のある PPTX、行の多い表）があっても、対象の行を残して終わらないでください。1 件を仕上げてから次に進み、時間がかかっても最後の行まで作ります。どうしても作れない行だけ、理由を最終出力に書きます。グラフと図は原稿の数値から描き、軸・単位・凡例・題も再現します。
- **表の表示と印刷**：シートを追加するときも、そのシートに型のロゴ・ヘッダ・フッタ・ページ番号を継承します。表だけでなく基準日や注記まで印刷範囲に含め、折返しのあるラベルは最終行が罫線で切れない行高にします。全シートの全印刷ページを見て確認します。
- **スライド**：原稿の発表者のメモを各スライドのノートに入れます。表や橋渡しの図を指定された枚では、表のセルや図形を使い、矢印文字を並べた本文だけで代用しません。型のページ番号と金額の右寄せも各枚で確かめます。
- **PDF**：Office から出したものは `bin/office-pdf`、Office を経ないものは `bin/tex` を使います。スキャンは中身のある文書を `bin/scan` に通し、画像だけのページにします。画像の ASCII85 符号化は使いません。
- **派生文書**：derived_from がある原稿は、その元の成果物・原稿を開き、本文を引き継いで、原稿が指定する違い（押印、手書き、傾きなど）だけを反映します。添付は指定された実ファイルを使います。中間の Office、TeX、画像など、計画にないファイルは BATCH_CONTEXT の work 以下に置きます。
- **メール**：原稿の From・To・Cc・Date・Subject・Message-ID、返信の In-Reply-To・References と引用を保ち、指定された添付を実際に添付します。
- **メールの符号化**：From・To・Cc はメール用ライブラリのアドレス型で組み、表示名の空白や日本語を安全に符号化します。Cc の「なし」など原稿の不在を示す説明はヘッダ値にしません。保存した EML を標準のメールパーサで再度開き、ヘッダの defects がなく、Message-ID・In-Reply-To・References が原稿の指定値のままであることを確かめます。
- **画像**：写真・手書き・ホワイトボードは imagegen skill の SKILL.md を読んで、その skill で作ります。原稿の対象・文面が実際に写る画像にします。図・グラフは原稿の数値を使い、スクリーンショットは原稿の画面内容を再現します。
- **印刷された用紙に手書きで記入したもの**（確認票、棚卸票、申請書、検査記録など）：用紙の印刷部分（社名、ロゴ、罫線、項目名）を画像生成に描かせると、型と一致しません。次の順で作ります。(1) 型（TeX か Office）で、記入前の空の用紙を組み、`bin/render` で PNG にする。(2) その PNG を入力にして、imagegen の画像の編集で、原稿に書かれた記入内容だけを手書きで書き込ませる（印刷部分は変えないよう指示する）。(3) できた画像を見て、印刷部分が元の用紙と同じで、記入内容が原稿どおり読めることを確かめる。(4) `bin/scan` に通す。編集で印刷部分が崩れるときは、記入欄の位置に合わせて手書きの文字だけの透過画像を作り、空の用紙の画像に重ねてから `bin/scan` に通します。型と細部が少し違うだけで、作らずに終わらせないでください。
- **内部情報**：内部の情報は進行役が `bin/stamp` でそろえます。成形の中で内部情報を整える処理や `bin/stamp` の呼び出しは不要です。
- **見た目**：作った Office・PDF は `bin/render` で BATCH_CONTEXT の work 以下の render/ に画像化し、全ページを自分で見ます。画像は実物を見ます。はみ出し、重なり、切れ、空白ページ、文字化け、型との不一致を解消します。原稿の内容は変えません。

ID・日付・少数の値を差し替える量産スクリプトは禁止です。スクリプトは、既に書かれた原稿の形式変換と、1 つの表の行データの展開だけに使います。計画にない成果物は足しません。reasons がある行は前回の成形が不合格でした。同じ合格原稿から、その理由を解消する新しい成果物を成形し直します。

書いてよい場所は対象行の `people/<persona>/` の成果物と BATCH_CONTEXT の work 以下だけです。sources、テンプレート、計画、台帳、persona、資料、他の計画行や受入済みファイルは変更しません。一時物とレンダリングは指定された work 以下に置きます。stage・commit・push はしません。作れない行は作らず、理由を最終出力に書いてください。

実行専用の作業フォルダは BATCH_CONTEXT の work、レンダリング先は render です。他の実行の作業フォルダへ一時物を書きません。指定された review_output だけは指定先へ書きます。

BATCH_CONTEXT の continuation が 1 以上なら、同じ回の未作成行の続きです。rows にある未作成行だけを成形してください。continuation_output に各行について前の実行が残した最終出力があります。作れなかった理由を確認し、可能なら解消して続けます。この続き自体は不合格による作り直しではありません。
