# 依頼からファイル計画を書く

指示の「読むファイル」に示されたパスを用途に従って開いてください。資料の本文は指示に埋め込まれていません。事実の台帳は、対象の行（計画前は依頼）に関係する案件・出来事の見出しを検索し、該当する部分を読んでください。
AGENTS.md、SPEC.md、runbooks/PRODUCTION.md、runbooks/REVIEW.md、personas/README.md を読み、依頼と persona 定義、過去の progress/<persona>/*.md を確認してください。
BATCH_CONTEXT の plan に Markdown 表を作ってください。列は「パス・日付・作り方・内容・関連・先に要るもの」。パスは people/<persona>/ からの相対パスです。

計画の質が、この batch の成果物の質を決めます。次を守ってください。

- **仕事の流れとして計画する**。依頼の範囲で実際に起きること（依頼、下書き、指摘、改訂、会議、決定、連絡、後始末）を先に時系列で考え、そこで生まれるファイルを並べる。形式の種類を埋めるために行を作らない。
- **「内容」は固有に書く**。誰が、誰に向けて、何について、どの数値・日付・結論で書いたかを 2〜4 文で書く。その行だけを読んで本文が書けること。他の行や過去の batch と、名前・日付・数値だけが違う行を作らない。
- **整いすぎない**。完成版だけでなく、下書き、赤字の入った版、古い版、自分用のメモ、うまくいかなかった試み、関係の薄い社内連絡も、実際にありそうな割合で入れる。
- **名前と置き場所**は、persona 定義の「人物」の整理の癖と「フォルダ構成」に従い、その人が付ける名前にする。その人の言語で付ける。連番だけの名前、形式名、制作の区分を使わない。
- **日付**は period の内側で、出来事の順序と合わせる（返信は元のメールより後、PDF は元の Office 文書より後）。`2026-03-06 18:42` の形で、その人の勤務の時間帯にする。
- **作り方**は PRODUCTION.md 3 節の定義どおりに書く。Office と PDF の型は templates/<persona>/README.md に載っているものを使い、足りない型だけをこの段階で templates/<persona>/ に作って README.md に足す。個人のメモなど、型を使わないのが自然なものは `office:なし` のように書かず、作り方を `text` や型なしの名前（README.md に「型なし」として載せる）にする。
- **形式の割合**は persona 定義の目安に、これまでの受入分と合わせて近づける。ただし仕事の流れを優先する。
- **件数**は依頼の目安の 0.5〜1.2 倍かつ 60 件以下。件数のために内容を薄くしない。

あわせて `progress/<persona>/facts.md`（事実の台帳）を更新してください。制作は 10 件ずつ別々の実行で行われるので、複数のファイルにまたがる事実をここに書いておかないと食い違います。

- 複数のファイルにまたがる事実だけを、案件・出来事ごとの見出しの下に、1 項目 1〜2 行で書く。見出しに batch 名は使わない。
- 文書番号、共有する金額・日付、会議の出席者、メールの順番、締切など、複数のファイルの整合に必要な事実を簡潔に残す。
- 1 つのファイルの中だけで完結する細部（表の全部の行や文面）は台帳に書かず、原稿に任せる。
- メールのスレッドを台帳に書くときは、件名、誰から誰へ、日時、順番を書く。Message-ID を書くなら、メールソフトが付ける形（長いランダムな英数字列か UUID に `@送信元ドメイン`）にし、件名・案件名・人名・日付など人が読める語を使わない。
- 既にある項目は変えず、書き直して増やさない。足りない共通の事実だけを追記する。

persona 定義の「仕事の流れ」に無い出来事が要るときは、時期・相手・数値・結論を付けて追記してください。既にある設定と受入済みのファイルに矛盾する変更はしません。

不合格理由が BATCH_CONTEXT の reasons にある場合、その理由を解決して計画全体を書き直してください。
書いてよい場所は progress/<persona>/、templates/<persona>/、指定された work、persona 定義の「仕事の流れ」への追記だけです。成果物はまだ作りません。
一時物は BATCH_CONTEXT の work 以下。資料と他 persona を変更せず、stage・commit・push はしないでください。

実行専用の作業フォルダは BATCH_CONTEXT の work、レンダリング先は render です。他の実行の作業フォルダへ一時物を書きません。指定された review_output だけは指定先へ書きます。

「先に要るもの」は同じ batch 内の前提となる行のパスをカンマ区切りで書き、無ければ空にします。循環させません。「関連」は参照関係で、原稿の実行順序には使いません。「読むファイル」に指定された進行中の batch の依頼と計画を読み、パスと内容を重ねず、他 batch の計画・依頼は変更しません。
