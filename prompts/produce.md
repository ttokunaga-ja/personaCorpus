# 対象の計画行を1件ずつ制作する

AGENTS.md、SPEC.md、runbooks/PRODUCTION.md、runbooks/REVIEW.md、persona 定義、事実の台帳、テンプレート一覧と実際の型を読んでください。REVIEW.md の観点で 1 つでも当てはまるファイルは破棄されます。
制作するのは BATCH_CONTEXT の rows だけです。パスは people/<persona>/ からの相対パス。全体計画は文脈として使います。

- **1 件ずつ、その人として書く**。計画の「内容」にある出来事・数値・結論を本文に入れ、その文書の種類として実務で使える中身と長さにする（調整表なら明細と差異の内訳、議事録なら出席者・決定事項・担当と期限、提案書なら金額と条件）。書き手の立場、相手との関係、言葉づかいを出す。言語は persona 定義に従う。
- **事実を合わせる**。人名、役職、金額、日付、文書番号、スレッドは、persona 定義、事実の台帳、計画の「関連」のファイルと一致させる。関連のファイルが既にあれば開いて読む。台帳に無い細部を決めたら、最終出力に書く（台帳は変更しない）。
- **表は計算が合う**。XLSX は値ではなく数式で合計や差異を出し、数式の結果も保存する。本文と表、グラフと表の数値を一致させる。
- **型**。Office は templates/<persona>/ の型を開いて中身を入れる。自社の文書は自社の型、社外から届いた文書はその相手の型。計画の「作り方」に従う。
- **PDF**。Office から出したものは bin/office-pdf、Office を経ないものは bin/tex、スキャンは中身のある文書を bin/scan に通す。
- **メール**（eml）は、From・To・Cc・Date（その人のタイムゾーン）・Subject・Message-ID を付け、返信は In-Reply-To と References、引用をそろえる。添付があるなら実際に添付する。アドレスは persona 定義のものを使う。
- **画像**。写真・手書き・ホワイトボードは imagegen skill を読んでその skill で作る。グラフと図は文書の数値から描く。スクリーンショットは、その画面に見える内容を持つものにする。
- **見た目を確かめる**。作ったら bin/render で画像にして自分で見て、はみ出し、重なり、空白のページ、文字化けを直す。レンダリングは指定された scratch/render/ 以下に置く。
- **書かないもの**。合成であることの注記、制作用の ID、「サンプル」「ダミー」などの断り書き、仮の文、コード。

ID・日付・少数の値を差し替える量産スクリプトは禁止です。スクリプトは、書いた内容の形式変換と、1 つの表の行データにだけ使えます。計画にないファイルは作りません。
reasons があるファイルは前回不合格でした。その理由を解決する新しいファイルを、同じ計画行から作り直してください。
書いてよい場所は people/<persona>/ と BATCH_CONTEXT の scratch 以下だけ。テンプレート・計画・台帳・persona・資料は変更しません。他の計画行や受入済みファイルも変更しません。
stage・commit・push はしないでください。作れない行は、作らずに理由を最終出力に書いてください。
