# persona の定義

persona ごとに 1 つの資料（`<persona>.md`）で、その人の PC の中身を決める。内容の基準は `SPEC.md` にある。制作のファイル計画（`progress/<persona>/<batch>.md`）は、この定義に合わせて書く。

## 書式

先頭に、`bin/check` が読む設定を置く。

```
---
persona: p14-finance-controller
period: 2024-04-01..2026-09-30
timezone: Asia/Tokyo
allowed_terms: batch payment
photo_dirs: Pictures
---
```

- `period`：ファイルの更新時刻が入る期間。
- `timezone`：その人がいる場所のタイムゾーン。ファイル計画の日付と、メールの時刻に使う。
- `allowed_terms`：制作の痕跡の検査（`trace`）で通す、その職種の正しい用語。複数語の句で書く。
- `photo_dirs`：文字のない写真を置いてよいフォルダ。

本文の節は次のとおりにする。

1. **人物**：氏名、役職、勤続、使っている PC と OS、言語、仕事の進め方とファイルの整理の癖。
2. **組織と関係者**：会社の概要、同僚（氏名と役割）、社外の相手（会社名、担当者）。メールアドレスのドメインは `.example` にする。
3. **仕事の流れ**：期間の中の主な仕事を、時期、相手、数値、結論が分かるように書く。ファイル計画はここから固有の内容を取る。
4. **フォルダ構成**：その OS の標準のフォルダ（Desktop、Documents、Downloads、Pictures、クラウド同期のフォルダなど）から始め、その人の整理の仕方で下位を決める。各フォルダに何が入るかを書く。
5. **形式の目安**：拡張子ごとの割合（%）。`SPEC.md` の「含める」の範囲で、その職種の実態から決める。
6. **規模の目安**：全体の件数の目安と、最初の区切り。
7. **書かないもの**：その職種で紛れ込みやすいが、この corpus に入れないもの。

## 共通の決まり

- 会社名、製品名、住所、電話番号は架空にする。実在の企業・製品と紛れる名前を使わない。電話番号は使わないか、明らかに架空と分かる形にする。
- 人名は、その国と世代でありふれた姓と名の組み合わせにする（日本なら 田中・山本・小林、米国なら Johnson・Garcia・Patel・Nguyen のように、その土地の実際の構成に合わせる）。珍しい姓や作った姓ばかりにしない。著名人と同じ氏名は避ける。20 persona の間で、同じ氏名の人物を作らない。
- 会社名は、2 つの名前をつないだ形にせず、その国・業種・規模の会社として普通の 1 つの名前にする。案件・製品・顧客には、Alpha・Beta のような記号ではなく固有の名前を付ける。
- 仕事には、うまくいかなかったこと、やり直し、古い版、個人的なメモも含める。整いすぎた PC にしない。
- 同じ内容が別の形式で存在するのは、実際にそうなる場合だけにする（例：XLSX から出した PDF、メールに添付した DOCX）。
