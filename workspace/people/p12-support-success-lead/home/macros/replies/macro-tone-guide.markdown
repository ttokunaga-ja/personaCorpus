# HelioDesk reply-macro tone guide

This guide covers the five approved reply macros cataloged in `reply-macro-catalog.yaml` for 2026-08-04: account verification, secure attachment request, Customer Alpha delay update, Customer Beta follow-up, and 4-hour SLA breach apology.

## Voice

Write like a calm, accountable support lead: plain language, short paragraphs, and one clear next step. Start by recognizing the customer’s effort or impact, then state what is known, what happens next, and when the next update is due. Use “we” for HelioDesk’s actions and avoid speculation.

## Boundaries

Do not imply a guaranteed fix, outcome, credit, or completion time. The 4-hour SLA is a response commitment, not a resolution promise. Never ask for or repeat a password, one-time code, recovery code, API key, access token, or full payment details. Attachment requests must point to the case-specific secure upload link and ask for only the material needed for the case.

## Internal handling

Operational annotations are for the agent only and must be removed before sending. Keep internal routing, queue information, and other customers’ case details out of customer-visible text. Address a single case using the approved placeholders from the catalog.

## Examples

Use the Customer Alpha delay macro when an owner has confirmed a delay; its synthetic recipient is `alpha-contact@customer-alpha.invalid`. Use the Customer Beta follow-up macro to check the result of a prior recommendation; its synthetic recipient is `beta-contact@customer-beta.invalid`. These examples are not a customer directory or recipient list.
