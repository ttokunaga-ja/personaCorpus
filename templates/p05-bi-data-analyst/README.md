# 吉田美佐の文書の型

織庭生活雑貨株式会社の営業企画部・分析室が使う型と、受領文書の発行元ごとの型。Officeファイルは開いて別名保存する。文書番号、対象期間、数式、版、作成者・確認者は原稿と計画に従う。

### b002での使い方

- FY26は1月始まり。7月1〜15日の資料では、月曜の営業会議で使う `oriba-weekly.pptx` と、対象日をそろえる `oriba-weekly.xlsx` を使う。XLSXの見出しは原稿に合わせて「対象期間／締め区分／計画GMV／実績GMV／計画比／照合根拠」などに組み替える。進行中の週は締め済み週と区別し、対象期間に実績・計画の共通の終端日を書く。
- 2026年7月1〜15日17時の累計は、実績25,260万円、同時点までの計画26,100万円、計画比96.8%、差はマイナス840万円。GMVはMTR-09の定義に沿って、取消と送料を除く返品前・税込商品受注額を使う。
- 岡田に渡す判断根拠の直接組版PDFは `oriba-analysis.cls` を使う。割引拡大による利益への影響が未確認であることと、拡大を見送る判断を記す。照合条件を正式な文書にする計画がある場合は `oriba-condition.docx` を使う。

### b003での使い方

- 2024年7月24日の通販返品286件の日別照合は `oriba-weekly.xlsx` を開き、表題を「通販返品　日別照合」、6行目を「日付／売上日基準（件）／売上日基準（円）／返金日基準（件）／返金日基準（円）／照合メモ」にする。日付は実日付、B〜E列は右寄せ、F列は左インデント1で組む。単位・対象期間をF5に入れ、集計の起点と終点を明記する。
- 初稿の同日扱いと照合後の集計は、原稿に合わせてシートや版を分ける。売上日と返金日が異なる63件は別表にし、売上月・返金月の組合せで同月内の日付ずれと月をまたいだものを分ける。月別集計では日付基準と対象月を列名か表題に明示する。件数・金額は各基準の列内で集計し、双方の合計を足し合わせない。月またぎの内訳は計画のTSVに残す。
- 月報注記は `oriba-analysis.docx`、照合条件を正式に残す文書には `oriba-condition.docx`。営業会議は `oriba-weekly.pptx` の表と図のレイアウトで、初稿との差と月報での読み方を示す。配布PDFは同じPPTXを `bin/office-pdf` で出力する。
- 受領CSVはDownloadsに受領時点の列と値で保存する。返金処理順の聞き取りはTXT、前田 裕介の確認は社内EML、差異の図は軸・単位・凡例を明示したPNGにする。購入者情報は含めない。

## 織庭の共通の意匠と番号

- ロゴは縦2本と横2本の帯を交差させた織り目と「織庭生活雑貨株式会社」の文字。藍 `304E67`、朱 `C5614F`、本文の墨 `303A42`。白地と淡い藍 `EAF0F3` は背景。朱はロゴ・図の差分など少量に使い、赤字の負数と意味を混同しない。
- Officeの欧文・日本語は Noto Sans CJK JP。Officeのテーマ、WordのNormal・見出し・表の段落、ExcelのNormal・既定セル・管理欄にも設定している。TeXの欧文は Liberation Sans、日本語は Noto Sans CJK JP。グラフPNGにも同じ色と日本語フォントを使う。増減の意味は色だけで示さず、符号と凡例も書く。
- ヘッダに会社・文書種別、フッタに営業企画部・分析室とページ番号。Excelは用紙上端の社名と印刷ヘッダ、用紙下端の部門・ページ番号を持つ。PowerPointはマスターの右上に「営業会議資料」を表示し、ページ番号は成形時に実スライドへ追加する。
- 社内文書番号は `ORI-BI-YYYYMM-用途-連番`。用途は報告・確認・連絡・週報・照合など。実際の値は計画と事実台帳で確定する。同じ文書の訂正前後は同番号で版を分け、会議提出日・訂正日・対象期間を区別する。型にはダミーの番号や日付を入れていない。
- 他personaの既存型（p14のCedar Works、親会社・銀行・仕入先）を確認した。Cedarの深緑・木材ロゴ・下部の簡素な部門表記とは、織り目、藍と朱、PowerPointの下端帯で分けた。

## Word

`Document(型)`で開く。Normal（10.5pt、段落後7pt、行間1.18）、Title（24pt）、Heading 1（15pt）、Heading 2（12pt）、Caption（9pt）を使う。いずれも日本語フォントを明示。Titleの題名下罫線は藍 `304E67` を直接指定し、テーマのaccent1も同じ藍にする。表紙は追加せず、Titleの後に文書番号・版・日付・作成／確認者、次に本文を置く。

表は必要な場合だけ追加し、`Oriba Table` を指定する。先頭行に `Oriba Table Header`（9pt・白・太字）、明細に `Oriba Table Body`（9pt）を指定。先頭行は型の表スタイルで藍背景になる。列幅の合計を本文の幅146mm以内に収め、右寄せ数値の次に来る文字セルの段落は左に3mm空ける。型に空の表や仮の本文はない。

`Oriba Table` の行設定で改ページによる行の分割を禁止している。PDF変換時にも有効になるよう、成形では行を追加し終えたあと、見出し・明細・合計の全行に `w:cantSplit` を直接設定する。さらに先頭行に `w:tblHeader` を設定して、続きのページでも見出しを繰り返す。

```python
from docx.oxml import OxmlElement

for row in table.rows:
    properties = row._tr.get_or_add_trPr()
    properties.insert_element_before(
        OxmlElement("w:cantSplit"), "w:trHeight", "w:tblHeader"
    )
table.rows[0]._tr.get_or_add_trPr().append(OxmlElement("w:tblHeader"))
```

`bin/render` で全ページを開き、続きのページでは繰り返し見出しの直下に明細が入り、改ページ前後で同じ行の途中が分かれていないことを確認する。

## Excelの行・式・印刷

1. `load_workbook(型)`で開く。1行目は社名、2行目は表題。管理欄は3〜5行目、各24pt高。B3:D3=文書番号、F3=版、B4:D4=作成者、F4=基準日、B5:D5=確認者、F5=単位・対象期間。B:Dは各行で結合済みで、入力は左上セルB3・B4・B5へ行う。ラベルはA列・E列。入力先の空セルにもNoto Sans CJK JP・9pt・墨・左寄せ・縦中央・左インデント1を設定済み。文書番号の全文（例 `ORI-BI-202607-週報-01`）と `石井美智（確認依頼）`、隣接する版・日付・単位期間を埋めて1行で印刷する。基準日は実日付に `yyyy-mm-dd`、単位期間は例えば `円／2026-07-01〜2026-07-15`。文字の縮小は使わない。幅を変えるときも結合入力先の実幅を確保し、全管理欄の1行表示を印刷確認する。長い説明は本文の注記へ移し、単位は必ず明記する。
2. 6行目が列見出し。左寄せ・上揃え・折返し・左インデント1を設定済み。表題、列名と幅は原稿に合わせて変える。列を追加するときは既存の見出しセルの書式をコピーし、社名・表題の結合と印刷範囲を新しい表幅に揃える。型の最終セル行は6。7行目以降に書式だけの行、仮の合計、未確認値は置いていない。
3. 原稿の実明細のみ7行目から追加する。NamedStyleの `OR Text`（10pt、左寄せ）、`OR Amount`（10pt、右寄せ）、`OR Note`（9pt、左寄せ）を各セルに指定する。いずれも上揃え・折返し。文字用の `OR Text` と `OR Note` は左インデント1（1文字分）を型に持つ。列を追加・並べ替えするときも、右寄せ数値の右隣の文字列には必ずこのインデントを維持する。先頭の番号列の右隣も同様にし、「34,338 有効」や番号と氏名が一続きに見えないか画像で確認する。金額は `#,##0;[Red](#,##0);"—"`、率は原稿どおり `0.0%` 等、日付は実値に `yyyy-mm-dd`。番号は文字列として保持する。空欄や未確認値を0にしない。
4. 明細の行高は、最も多く折り返すセルに合わせる。照合表の対象週を年月日付きで入れて2行になる場合は、36ptを目安に確保し、印刷画像で末尾まで読めることを確認する。合計が意味を持つ場合だけ最終明細の次に行を追加し、ラベルと計算セルへ `OR Total`（淡藍、太字、上細線・下二重線）を指定する。ラベルは左寄せ・左インデント1へ変更し、数値は右寄せ。原稿の `SUM` や差額式を実セルの範囲へ入れる。合計行の計画比は、同じ対象期間の実績GMV合計を計画GMV合計で割る。週報の異なる指標を単純加算しない。訂正後は原稿の式で算出し、計算結果は `bin/recalc` で確認する。
5. 注記も原稿にある場合だけ最終行の下へ追加する。表全幅の注記はその行のA:Fを結合し、A列のセルに `OR Note` を指定する。折返しに応じた行高と実最終行までの印刷範囲を設定。A4横、幅1ページ・高さ自動、1〜6行を繰返し、C7で固定。数字や根拠が縮みすぎる場合は表やシートを分ける。受領時点のCSVをこの型で装飾・上書きしない。

## PowerPoint

`Presentation(型)`を開き、`slide_layouts[0..4]`を選ぶ。題はidx=0、本文または図表領域はidx=1、2段の右はidx=2。本文20pt、題28ptを継承。表紙の副題に文書番号・版・提出日・作成者を入れる。全レイアウトはマスターのロゴ・社名・文書種別「営業会議資料」・フッタを継承する。

表・図のobjプレースホルダは配置の基準（左0.7、上2.0、幅11.9、高さ4.5インチ）。実表・グラフ・画像をこの内側に置き、置換後は不要なプレースホルダを削除する。表の見出しは藍に白字、明細は白または淡藍、数字は右寄せ。右寄せ数値の次に来る文字セルは左余白を0.20インチ取る。本文は原則20pt、注記12pt以上。各スライド右下の白地（左12、上6.95インチ付近）へ実ページ番号を墨 `303A42` の10ptで追加する。原稿の発表者メモも保持する。訂正前の資料を後から訂正済みの内容に置き換えない。

## TeX

`TEXINPUTS="$PWD/templates/p05-bi-data-analyst:" bin/tex <scratch内の入力.tex> <scratch内の出力.pdf>` を使う。

- `\documentclass{oriba-analysis}`。`\AnalysisHeading{題}{文書番号}{版}{作成者／確認者}{日付}`、`\AnalysisSection{見出し}`、`\AnalysisNote{注記}` を使用。
- 表は `\begin{AnalysisTable}{列指定}`。最初に見出し行と `\\\midrule\endhead` を置く。見出し行は `\rowcolor{oriba}` と各セルの `\textcolor{white}{見出し}`、強調が必要な行は `\rowcolor{pale}` を使う。金額はr列、説明はp列を使い、列間の余白も含めて本文幅168mm以内に収める。行間は `\\`、最終行に改行を重ねない。実際の明細・必要な合計だけを呼出し側で書く。
- 既存Office資料の配布PDFは完成したOfficeから `bin/office-pdf` で出し、TeXで別内容を作り直さない。

### 英語購買月報

- `\documentclass[buying-monthly]{oriba-analysis}` を選び、`\BuyingMonthlyHeading{題}{文書番号}{版}{発行日}{作成者}{宛先}{報告対象期間}` を冒頭に置く。文書番号は `ORI-BI-YYYYMM-月報-NN`（発行年月・連番2桁）。日付は `8 September 2026` のように表記する。左上に織り目と正式社名、右上に `Monthly Buying Report`、下端に `Sales Planning | BI Analysis` とページ番号が出る。
- 本文と節見出しは英語で書く。節・注記・表には上記の `\AnalysisSection`、`\AnalysisNote`、`AnalysisTable` を使う。数量は `units`、金額を載せる場合は `JPY` のように表の列見出しか注記に単位を入れる。実績、従来見込、改定見込、配荷案は列名または節を分け、各対象期間を添える。数値の右隣に説明列を置く場合は、列指定で `r@{\hspace{5mm}}p{...}` のように間隔を取る。

## 社外文書・型を使わない記録

b001〜b003のOffice文書とPDFは社内資料。受注システムのCSVは社内の受領表。前田との照合メールはEMLで保存する。

### 薄帆リサーチの設問票

- 2026年8月の再来店意向調査で坂本から受領する設問票PDFは、計画の作り方に `tex:usuho-questionnaire.cls` を指定する。受領集計CSVと回答EMLは元の形式で扱う。吉田の設問別検算は `oriba-weekly.xlsx`、報告書は `oriba-analysis.docx`、旧見出しを含む会議資料は `oriba-weekly.pptx` を使う。
- 帆を模した大小の三角形と船体の線に、薄帆リサーチ合同会社の社名を添える。本文と社名は焦茶 `49392E`、帆の一部・設問番号・フッタの細罫は黄土 `976015`、管理欄の地は砂色 `F5EDDF`。日本語は Noto Serif CJK JP、欧文は Liberation Serif。左右余白25mm。表題と管理欄は冒頭に置き、各ページに社名・「設問票」と文書番号・ページ番号を出す。
- 設問票の文書番号は `UHR-QST-YYYYMM-NN-RNN`（発行年月、同月の設問票連番2桁、改訂番号2桁）。改訂時は末尾の改訂番号を更新する。表題、番号、発行日、作成者は原稿と計画に従い、照合日と発行日を区別する。管理欄はラベルと値の2列で項目ごとに1行ずつ取り、長い値は値列内で折り返す。
- 上の TeX コマンドを使い、入力に `\documentclass{usuho-questionnaire}`、本文冒頭に `\UsuhoHeading{題}{文書番号}{発行日}{作成者}` を書く。その後に原稿の回答方法や注意書き、設問を原稿順に置く。設問は `\begin{UsuhoQuestion}{設問番号}{設問文}` と `\end{UsuhoQuestion}` で囲む。回答方法・分岐指示は設問内の段落に置く。選択肢がある設問では、その中に `\begin{UsuhoOptions}` と `\end{UsuhoOptions}` を置き、実際の選択肢ごとに `\UsuhoOption{回答コード}{選択肢の文言}` を1つ書く。番号と文言を4mm離し、長い文言は本文の位置で折り返す。設問と選択肢は一緒に改ページするので、各設問は1ページに収まる量を保つ。
- `bin/render` で全ページを確認し、管理欄とフッタの文書番号全文、設問番号と文面、コードと選択肢の分離、続きのページのヘッダとフッタを確かめる。

### 型を使わない記録

CSV・TSV、EML、吉田の作業中のTXT・Markdownメモにはロゴや文書番号を付けない。計算条件の正式な記録にはWord、手元の検討には無装飾のメモを使い分ける。グラフPNGは元データ・軸・単位・凡例を原稿に従って描き、会社の用紙画像にしない。

## 型の内部情報

Officeの型の既定作者・更新者は吉田 美佐。内部の作成日時と更新日時はともに `2025-10-01T00:00:00Z`。成形した成果物には各原稿の日付と人物を改めて設定する。WordのTitle下罫線とテーマaccent1は藍 `304E67`。
