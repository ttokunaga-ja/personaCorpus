# 中山由紀子の文書の型

金原産業精機株式会社の品質保証部が使う型。b001 の BR-2410／NCR-026 の発見・保留・選別・出荷判断（2026年8月）に必要なものを用意した。Officeは通常のDOCX・XLSX・PPTXとして開き、別名保存する。型には固定の文書種別・社名・列名・スタイルだけがある。案件本文、文書番号、日付、測定条件、署名、仮の集計は入れていない。既存のp18の型、計画、facts.mdは作成時点でなかった。

竹田の確認書はメールだけの回答を文書に水増しするためには使わない。顧客への金原発の説明は金原の型を使う。他の供給者・校正先の文書は今回の範囲にないため追加しない。

## 意匠・番号

金原のロゴは角形のコの字枠と、上側の寸法線・両端の短線、社名文字からなる。青緑 `16686A` と鋼灰 `424F59` の2色を基本とし、淡青緑 `EAF2F1` は表の補助背景。236人規模の部品メーカーの実務書式として、余分な装飾・独立表紙を付けない。Word・Excelの図形ロゴは埋込み画像、PowerPoint・TeXは同じ構成の図形。日本語と欧文のOffice書体は Noto Sans CJK JP、TeXの日本語も同じ、欧文は Liberation Sans。環境のフォントを使う。

竹田のロゴは菱形と社名文字、茶 `795E37` と鋼灰。書体は Noto Serif CJK JP。ヘッダに竹田の社名、フッタに品質課とページ番号。金原の青緑・寸法枠とは区別する。

金原のWord・TeXヘッダはロゴと社名、フッタは品質保証部とページ番号。Excelは上段の社名・ロゴと印刷フッタ、PowerPointはマスターの社名・ロゴと品質保証部。PowerPointの実ページ番号は成形時に右下へ追加する。

文書番号は金原が `KS-QA-YYYY-用途-連番`（用途：不適合NCR、判定REL、連絡COM、測定MES、選別SEL、説明BRF、現場票FLD）。既に案件番号NCR-026があるため、案件番号と文書番号は分ける。竹田は `TK-Q-YYYY-連番`。番号の実値と版は計画・台帳で決める。同一報告のDOCXと配布PDFは同番号・同版。個人メモ、装置CSV、写真には番号を強制しない。

他personaのp05・p12・p17のREADMEを読み、p14の `cedar-review.docx` のヘッダとスタイルも実際に開いて比較した。織り目の藍朱、枝と灯の紫、柱梁の青灰橙、木材の深緑とは、寸法線を持つ青緑の工場書式で区別した。他personaの型は変更していない。

## Word

- `Document(型)` で開く。Normal 10pt、Title 22pt、Heading 1 13pt、Heading 2 11pt、Caption 8.5pt。行間1.15、段落後6pt。左右20mm、上27mm、下22mm。表紙なし。
- 題の次に原稿の文書番号・版・日付・対象品種・ロット・作成／確認／承認者を `Record Metadata`（9pt）で追加する。顧客連絡には宛先も入れる。見出しと本文は原稿から作る。型に仮の記入欄や本文はない。
- 表は必要時に追加し、`Record Table` を指定。先頭行の「最初の行」を有効にし、`w:tblHeader` を設定して改ページで繰り返す。先頭行は `Record Header`（9pt白太字）、明細は `Record Cell`（9pt）。先頭行背景は自社が青緑、竹田が茶。罫線は灰。文章左寄せ、数値右寄せ、実内容に応じて幅と高さを決める。固定行高・空の明細は作らない。
- 注記は `Record Note`。写真を載せる場合は幅170mm以内、縦横比を維持し、Captionに撮影日・方向・測定箇所を原稿どおり記す。
- NCR報告は要求値・観察値・保留範囲・処置・継続事項を分ける。出荷判定は選別の実績・承認対象・隔離品の扱い・承認を分け、是正活動の完了と混同しない。型は根本原因や未確認の測定条件を決めない。

## Excel：明細・合計・印刷

型は6行まで。1行目は社名とロゴ、2行目は題、3〜4行目は管理情報のラベル、6行目は列見出し。7行目以降に空の書式行・合計欄・仮の式はない。NamedStyleは定義だけを持つ。

1. `load_workbook(型)` を開き、B3=文書番号、D3=版、F3=基準日、B4=作成者、D4=確認者、F4=条件・単位を原稿から入れる。B3は型に設定済みの Noto Sans CJK JP 9pt・左寄せ・上下中央・折返しを維持し、3行目は32ptとする。標準番号 `KS-QA-2026-MES-026`／`KS-QA-2026-SEL-026` はB3内に収め、必要に応じて折り返して表示する。B3に別のNamedStyleを上書きしない。番号がさらに長くなる場合は3行目の高さを増やし、印刷プレビューで末尾まで表示されることを全ページ確認する。F3は実日付に `K Date`。測定器・分解能・測定箇所・対象ロット・要求値が長い場合は管理情報や実注記として追加し、行高を広げる。未確認の分解能を推測しない。
2. 実明細を7行目から追加。`K Text` は10pt左寄せ、`K Dimension` は10pt右寄せ `0.00`、`K Count` は整数右寄せ `#,##0`、`K Date` は `yyyy-mm-dd` 中央、`K Note` は9pt左寄せ。すべて上揃え・折返し、下細罫線。日付を文字列にせず、ロットと識別番号は文字列。文量に応じて行高を設定する（短い明細32pt程度）。欠測を0で埋めない。
3. 原稿に必要な場合のみ最終明細の次へ集計を作り、ラベルと実数式のセルに `K Total`（太字・淡青緑・下二重線）を適用。ラベルは左寄せに変える。選別表のD〜F列は対応する実明細範囲への `SUM`、確認数=適合+隔離の整合も確認する。測定順や測定値の無意味な合計は作らない。600／42／558は実際の原稿と対象範囲に従い、見本の行から採用しない。式は `bin/recalc` で再計算する。
4. 注記も実内容がある場合だけ追加。印刷範囲を `A1:G実最終内容行` に更新。オートフィルタは `A6:G最終明細行` にし、合計行は含めない。A4横、幅1ページ・高さ自動、1〜6行の繰返し、C7固定、フッタに部門とページ番号。列の増減時はロゴ・題の範囲、幅、印刷設定も揃える。縮小で読みにくい場合はシートを分ける。

## PowerPoint

`Presentation(型)` を開き、`slide_layouts[0..4]` の表紙、見出しと本文、2段、表、図を使う。題idx=0、本文または図表領域idx=1、2段の右idx=2。表紙の題34pt、副題18pt、他の題30pt、本文20pt。表紙の副題には文書番号・版・日付・発表者を入れる。各実スライド右下へ実ページ番号を追加する。

表・図のidx=1は汎用オブジェクト領域。左0.7、上2.0、幅11.9、高さ4.7インチの範囲に実表・図・画像を追加し、置換したプレースホルダを除く。表は青緑白字の見出し、本文は鋼灰、文字は原則20pt。図は軸・単位・凡例と測定箇所を明記し、色だけで判定しない。発表者ノートは原稿にある場合だけ保存する。

## TeX・PDF・スキャン

`TEXINPUTS="$PWD/templates/p18-manufacturing-quality-engineer:" bin/tex <scratch内の入力.tex> <scratch内の出力.pdf>`。`\documentclass{kanehara-field}` を使う。

- `\QualityHeading{題}{文書番号}{対象品種・ロット}{実施日}{記録者}`、`\QualitySection{見出し}`、`\QualityNote{注記}` を必要なところだけ使う。
- `SelectionTable` 環境は照合単位、確認数（個）、判定、隔離・引継ぎの確認、確認者の5列。原稿の実明細を `&` で区切り、行末を `\\\hline` とする。見出しはページごとに繰り返す。長文の記録を1行に詰めず、行単位で改ページできる量にする。
- 型に空の記入行・仮署名・例文はない。印刷原紙として手書き欄が必要な実文書では、原稿に沿って成形時に作る。現場の手書き記録そのものはimagegen skillを読み、実際の筆記内容のある画像として制作する。活字のPDFを手書き記録の代用にしない。最後に `bin/scan` に通す。
- 不適合報告のPDFは完成したDOCXから `bin/office-pdf` で出す。Officeの内容をTeXで別に書き直さない。

## 型を使わないもの

装置CSVは素の測定出力、EMLは送受信ヘッダ・本文・必要な添付を持つメール、TXTは中山の作業メモ。写真はPicturesの現物・測定箇所、管理図PNGは実測値から描く図であり、Officeの用紙枠を付けない。管理限界と仕様限界を混同せず、単位・対象期間・サンプル定義を原稿どおり示す。写真・手書き制作時にはimagegen skillを読む。本工程では写真や手書きの代用品を作っていない。

## 見本と検査先

初回制作の見本は `scratch/p18-manufacturing-quality-engineer/b001/work/templates-0001/`。`examples/` に各型と同じstemの内容入り見本、`render/` に `bin/render` の画像を置く。Wordは各1見本、Excelは各3行・48行の見本（`-3`／`-48`）、PowerPointは全5レイアウト、TeXは同名の `.tex` と `.pdf`。画像フォルダ名は見本のstemに `-docx`・`-xlsx`・`-pptx`・`-pdf` を付けたもの。

見本は組版確認専用であり、計画・原稿・事実台帳の根拠ではない。見本の数量・日付・行や照合単位を成果物へ転記しない。ログは作業先の `*.log`、実行結果は `render-results.json`、構造検査は `structure.json`。scratch削除後は新しい実行のscratchで内容を入れて再検査する。別実行のtemplates-reviewと統括の受入は後続工程。

初回制作時の確認では、8種類・10見本・計20ページを `bin/render` で画像化し、全ページを目視した。`bin/tex` の組版も成功。Wordの既定テーマの題下線とPowerPointの文字色・揃え・影を修正し、修正対象を再レンダリングした。Excelの48明細の見本は各4ページで、見出しの繰返しと最後の合計まで確認した。構造検査ではWordが題のみで表の実体なし、Excelが6行までで式なし、PowerPointが1マスター・5レイアウト・スライド0枚であることを確認。Office型の作者・更新者と日付は金原が中山由紀子、竹田が谷口美奈美、2026-08-01 09:00 JSTに設定し、`bin/stamp` で制作用ライブラリのプロパティを除いた。成果物の日時・作者は成形段階で原稿に合わせて改めて設定する。

書式資産の制作のため、Red→Greenのテストに代えて組版・画像・ファイル構造を検証した。削除・置換対象となる既存のp18型はなかった。受入済み成果物・他persona・persona定義は変更していない。stage・commit・pushも行っていない。


### 文書番号欄の修正（templates-0003）

レビューで、両Excel型のB3に標準の文書番号を入れると末尾が隣のC3「版」に遮られることが判明した。B3に9ptの指定フォント・折返し・上下中央を設定し、3行目を32ptに変更した。列幅と明細列の構成は維持した。上記Excel手順1にも型の設定と長い番号の確認方法を反映した。

修正の見本は `scratch/p18-manufacturing-quality-engineer/b001/work/templates-0003/examples/` の `kanehara-measurement-3.xlsx`、`kanehara-measurement-48.xlsx`、`kanehara-sorting-3.xlsx`、`kanehara-sorting-48.xlsx`（同名PDFも保存）。初回見本をこの実行先へ読み込み、文書番号を指定形式に置き換え、修正した管理情報の書式を適用した。画像は同作業先の `render/<見本stem>-xlsx/`、実行結果は `render-results.json`、書式の修正前後は `structure.json`。見本は組版確認専用であり、事実の根拠には使わない。

`bin/render` は4見本とも終了コード0、3明細は各1ページ、48明細は各4ページ（計10ページ）。全ページの画像を目視し、標準番号の末尾026と隣の版が重ならず、明細・見出しの繰返し・選別合計も収まることを確認した。全10ページでPDFの文字抽出にも番号全文が含まれた（`pdf-number-check.json`）。両型は引き続き6行まで、B3は空、仮の明細・数式なし。書式修正のためRed→Greenの代わりに構造検査・PDF文字抽出・画像確認を行った。受入済み成果物は変更していない。今回変更した資産は両Excel型と本READMEだけで、stage・commit・pushは行っていない。
