# 中山由紀子の文書の型

金原産業精機株式会社の品質保証部と取引先の文書の型。2024年4月の不良分析と加工工程の見直し、同年7月の作業指示書の点検・改訂・旧版回収、同年10月の校正結果とロット再評価、2025年1月の工程FMEAと治具点検の改善計画、2026年4月の寸法要求の設計協議、同年8月の不適合・選別・出荷判断、同年9月の是正後の効果確認に使う。Officeは通常のDOCX・XLSX・PPTXとして開き、別名保存する。型には文書種別、社名、列名と書式を持たせる。番号、日付、人名、案件本文、明細は原稿をもとに成形時に入れる。

## 意匠・番号

金原のロゴは角形のコの字枠と、上側の寸法線・両端の短線、社名文字からなる。青緑 `16686A` と鋼灰 `424F59` の2色を基本とし、淡青緑 `EAF2F1` は表の補助背景。236人規模の部品メーカーの実務書式として、余分な装飾・独立表紙を付けない。Word・Excelの図形ロゴは埋込み画像、PowerPoint・TeXは同じ構成の図形。日本語と欧文のOffice書体は Noto Sans CJK JP、TeXの日本語も同じ、欧文は Liberation Sans。環境のフォントを使う。

竹田のロゴは菱形と社名文字、茶 `795E37` と鋼灰。書体は Noto Serif CJK JP。ヘッダに竹田の社名、フッタに品質課とページ番号。金原の青緑・寸法枠とは区別する。

双葉は高さ違いの2本の角形と社名、えんじ `702C46`、墨 `342C32`、見出しの淡紅 `F4E8ED`。日本語は Noto Serif CJK JP、欧文は Liberation Serif。右上にロゴと社名、下端に社名とページ番号。相手先は本文の左、発行情報は右に置く。

Wallaceは円に折れ線を入れたマークと社名。紺 `28354D` を題・見出し、黄土 `956018` をマークと題下の罫線、墨 `292A2E` を本文・数値に使う。英文本文と題は Liberation Serif、社名・ラベル・欄外は Liberation Sans、等幅のアドレスは Liberation Mono。ヘッダには社名と Dimensional Calibration、フッタには証明書番号と総ページ数付きのページ番号。証明書番号は発行元の `WG-YYMMDD-NN` 表記をそのまま転記し、金原側の表と照合する。2024年10月17日発行分はHG-02が `WG-241017-02`、HG-05が `WG-241017-05`。

金原のWord・TeXヘッダはロゴと社名、フッタは品質保証部とページ番号。Excelは上段の社名・ロゴと印刷フッタ、PowerPointはマスターの社名・ロゴと品質保証部。PowerPointの実ページ番号は成形時に右下へ追加する。

文書番号は金原が `KS-QA-YYYY-用途-連番`（用途：不適合NCR、判定REL、連絡COM、測定MES、選別SEL、説明BRF、現場票FLD、効果確認EFF、呼称分類CLS、箇所集計LOC、議事録MIN、作業指示WI、掲示版照合WIC、工程FMEA、工程検討REV、改善計画PLN、供給者工程監査の照合・提出物AUD）。既に案件番号NCR-026があるため、案件番号と文書番号は分ける。竹田は `TK-Q-YYYY-連番`、双葉は `FB-Q-YYYY-連番`。番号の実値と版は計画・台帳で決める。同一報告のDOCXと配布PDFは同番号・同版。個人メモ、装置CSV、写真には番号を強制しない。

金原は寸法線を持つ青緑の工場書式で、p17の梁のロゴと橙罫線やp14の木材をモチーフにした深緑と区別する。

## Word

- `Document(型)` で開く。Normal 10pt、Title 22pt、Heading 1 13pt、Heading 2 11pt、Caption 8.5pt。行間1.15、段落後6pt。左右20mm、上27mm、下22mm。表紙なし。
- 題の次に原稿の文書番号・版・日付・対象品種・ロット・作成／確認／承認者を `Record Metadata`（9pt）で追加する。顧客連絡には宛先も入れる。見出しと本文は原稿から作る。型に仮の記入欄や本文はない。
- 表は必要時に追加し、`Record Table` を指定。先頭行の「最初の行」を有効にし、`w:tblHeader` を設定して改ページで繰り返す。先頭行は `Record Header`（9pt白太字）、明細は `Record Cell`（9pt）。先頭行背景は自社が青緑、竹田が茶。罫線は灰。文章左寄せ、数値右寄せ、実内容に応じて幅と高さを決める。右寄せ数値の次が左寄せ文字なら文字段落を1字分（約3mm）字下げする。固定行高・空の明細は作らない。
- 注記は `Record Note`。写真を載せる場合は幅170mm以内、縦横比を維持し、Captionに撮影日・方向・測定箇所を原稿どおり記す。
- NCR報告は要求値・観察値・保留範囲・処置・継続事項を分ける。出荷判定は選別の実績・承認対象・隔離品の扱い・承認を分け、是正活動の完了と混同しない。根本原因や測定条件は根拠となる原稿を参照する。
- 効果確認書は、対象ロット・確認数、測定箇所・条件と照合結果、根拠資料、監視項目・担当・判定基準・逸脱時の扱いを分ける。起案には案の版と回付先、決裁版には承認者・承認日と監視を条件とする決裁内容を入れる。決裁PDFは承認後の同番号・同版のDOCXから `bin/office-pdf` で出力する。

- 品質会議議事録は、開催日・出席者・記録者に続けて確認範囲、決定、持ち帰りの担当と期限を原稿から入れる。検査の追加で変えられる範囲と、製造側で確認する加工上の論点を区別する。配布PDFは同番号・同版のDOCXから `bin/office-pdf` で出力する。
- 工程検討（REV）・改善計画（PLN）は共通のWord管理欄に番号・版・日付・対象・起案者・確認者と回付または承認の状態を入れる。検討稿への設計コメントは該当箇所にWordのコメントとして記録する。改善計画は担当、実施条件、期限、確認記録を表で対応させ、配布PDFは同じ版のWordから書き出す。

- 供給者工程監査の所見案と正式報告（REV）にも `kanehara-process-review.docx` を使う。正式報告は宛先、監査日、発行日、対象、作成者と承認者を管理欄に記載する。指摘の実表を含む配布PDFは承認済みDOCXから出力する。
- BR-2410の加工側検討案は `kanehara-process-review.docx` を使い、加工上の事情・提案する範囲・影響を確認する箇所を原稿どおり記す。設計協議の記録は `kanehara-minutes.docx` を使い、現行要求、加工側の提案、設計側が要求を維持する理由と結論を記す。協議記録の配布PDFは `bin/office-pdf` で出力する。

### 校正結果に伴う出荷判定

`kanehara-release.docx` の題を原稿の題に置き換え、REL番号・版・日付・対象・作成者と、案なら回付先、確定版なら承認者と承認日を `Record Metadata` に入れる。どの使用器と原記録まで照合できたか、ロット別に適合を裏づける根拠、適合の証明に足りない記録・条件、保留中の処置と再確認の担当を記す。確定PDFは承認済みDOCXから `bin/office-pdf` で出し、その版と番号を引き継ぐ。

### 写真付き作業指示書と配布PDF

- 題の直下に指示書番号・版・発行日、対象品種・掲示先、改訂者・確認者を `Record Metadata` で記載する。改訂時は指示書番号を引き継ぎ、版と発行日を更新する。版や確認者は原稿から入れる。
- 一つの手順見出しに対し、作業者が見る位置、部品を置く向き、目印または基準面を本文に記す。対応する写真を本文に行内配置し、撮影方向と日付を `Caption` に記す。写真段落を次の段落と同じページに保つ設定にして、写真とキャプションを離さない。縦横比を維持し、掲示時の距離から識別に必要な基準面が読める大きさを取る。
- 現場配布用PDFは承認済みDOCXを `bin/office-pdf` で出力し、番号・版・掲示先を照合する。上田の赤字指示は書込みがある紙のスキャン控えとして扱う。

## Excel：明細・合計・印刷

型は6行まで。1行目は社名とロゴ、2行目は題、3〜4行目は管理情報のラベル、6行目は列見出し。7行目以降に空の書式行・合計欄・仮の式はない。明細用のNamedStyleはブック内の書式定義。既定のNormalは Noto Sans CJK JP 10pt・鋼灰。管理欄の入力セルにも同書体を設定済み。

1. `load_workbook(型)` を開き、B3=文書番号、D3=版、F3=基準日、B4=作成者、D4=確認者、F4=条件・単位を原稿から入れる。B3は Noto Sans CJK JP 9pt・左寄せ・上下中央を維持する。既存の配置をコピーして `wrap_text=False` とし、B列幅を24以上に取る。3行目は32ptを基準にする。標準番号 `KS-QA-2026-MES-026`／`KS-QA-2026-SEL-026` はB3に全文を1行で表示する。長い番号はB列をさらに広げ、全列が横1ページに収まるように列幅配分を見直す。管理欄をすべて入力した状態で印刷画像を開き、全ページで文書番号の末尾と隣の版・基準日まで読めることを確認する。F3は実日付を入力し、型の `yyyy-mm-dd`・中央揃えを維持する。F4はG4まで結合済み（工程FMEAの主表はJ4まで）。測定器・分解能・測定箇所・対象ロット・要求値が長い場合は管理情報や実注記として追加し、行高を広げる。未確認の分解能を推測しない。
2. 実明細を7行目から追加。`K Text` は10pt左寄せ、`K Dimension` は10pt右寄せ `0.00`、`K Count` は整数右寄せ `#,##0`、`K Date` は `yyyy-mm-dd` 中央、`K Note` は9pt左寄せ。すべて上揃え・折返し、下細罫線。日付を文字列にせず、ロットと識別番号は文字列。文量に応じて行高を設定する（短い明細32pt程度）。欠測は原稿の状態を記録する。数値右寄せ列の直後に文字左寄せ列が来る場合は、`K Text Indented` または `K Note Indented`（左インデント1、元の書体・罫線を継承）を文字列側に使う。寸法測定のF列は `K Text Indented`、選別・隔離のG列は `K Note Indented`。先頭の照合順を右寄せにし、直後が左寄せ文字なら同じ字下げを付ける。数値と文字が接して見えないことを印刷画像で確かめる。
3. 原稿に必要な場合のみ最終明細の次へ集計を作る。整数の集計値には `K Total`（`#,##0`）、治具の予備点検のmm集計値には測定型の `K Total Dimension`（`0.00`）を適用する。どちらも太字・淡青緑・下二重線。集計ラベルには `K Total` を使い、左寄せに変える。選別表のD〜F列は対応する実明細範囲への `SUM`、確認数=適合+隔離の整合も確認する。測定順や測定値の無意味な合計は作らない。600／42／558は実際の原稿と対象範囲に従い、見本の行から採用しない。式は `bin/recalc` で再計算する。
4. 注記も実内容がある場合だけ追加。印刷範囲を `A1:G実最終内容行` に更新。オートフィルタは `A6:G最終明細行` にし、合計行は含めない。A4横、幅1ページ・高さ自動、1〜6行の繰返し、C7固定、フッタに部門とページ番号。列の増減時はロゴ・題の範囲、幅、印刷設定も揃える。縮小で読みにくい場合はシートを分ける。

### BR-2410の寸法要求と実測範囲の比較

- `kanehara-measurement.xlsx` を開き、A2とシート名を原稿の題に合わせる。6行目のA〜Gは「区分、集計対象、下限 (mm)、上限 (mm)、実測最小 (mm)、実測最大 (mm)、測定条件・根拠」。列幅の目安は順に16、24、13、13、14、14、38。明細は順に `K Text`、`K Text`、C〜Fは `K Dimension`、Gは `K Note Indented`。実明細を7行目から作り、条件の折返しに合わせて行高を取る。

### 校正結果・ロット再評価表

- `kanehara-calibration-review.xlsx` を開く。両シートに同じMES番号・版・基準日・作成者・確認者・照合範囲を共通手順どおり入力する。B列は型の幅27を基準とし、B3は折返しを無効にして3行目は32ptとする。B4・D4・F4は折返し、4行目は38ptを基準に情報量に合わせて調整する。
- 「測定器別の偏り照合」のA〜Gには、使用器ID、証明書番号、分解能、偏り、単位、校正点、適用できる条件と原記録を入れる。順に `K Text`、`K Text`、`K Dimension`、`K Dimension`、`K Text Indented`、`K Text`、`K Note` を指定。偏りの向きは証明書で確認し、符号の定義と調整前後の区分を根拠欄か注記に記す。分解能と偏りは数値で入力し、証明書の桁数に合わせて表示形式を変える（mmで小数第3位まで記録した例は `0.000` と `+0.000;-0.000;0.000`）。複数の校正点を載せる場合は行を分ける。偏りは合計しない。
- 「ロット別の再評価」のA〜Gには、照合順、製造ロット、使用器ID、測定日、再評価結果、判断根拠・原記録、次の処置を入れる。順に `K Count`、`K Text Indented`、`K Text`、`K Date`、`K Text`、`K Note`、`K Note Indented` を指定。使用器IDで器別の表と照合し、実際に使った校正点や適用範囲が分かるように記す。適合を証明できずに出荷を保留した場合は、その根拠と確認に必要な処置を書く。
- 実明細は7行目から作り、行高は器別の短い明細で35pt、ロット別で43ptを目安に、折返しの行数に応じて調整する。1ロット1行で保留数を集計するときだけ、明細直後のE列に「保留ロット数」、F列に `=COUNTIF(E7:E最終明細行,"出荷保留")` を入れ、両セルに `K Total` を適用する。ラベルは左寄せ、数値は整数右寄せ。必要な注記は次の行のA〜Gを結合して `K Note` で入れる。両シートのフィルタ・印刷範囲は共通手順に従って更新し、`bin/recalc` で式を再計算する。全ページで番号末尾、日付、作成者と見出しが読め、偏りと単位、照合順とロット番号が接しないことを確認する。

### 工程FMEA

- `kanehara-pfmea.xlsx` の「工程FMEA」は A〜J を項目、工程、故障モード、影響・想定原因、現行の検出、S、O、D、RPN、参照・備考の順で使う。F〜Iは整数の `K Count`、Jは `K Note Indented`。RPNはその行のS×O×Dの式で計算し、集計欄は原稿で使うものだけを実明細の下に置く。

### 治具の予備点検集計

- `kanehara-measurement.xlsx` の共通管理欄と印刷書式を使う。B3にMES番号、F4に治具・見本・器・分解能を記す。6行目のA〜Gは「反復、測定日、治具ID、測点、比較差 (mm)、状態、測定条件・根拠」とし、明細に順に `K Count`、`K Date`、`K Text`、`K Text`、`K Dimension`、`K Text Indented`、`K Note` を適用する。比較差は数値で入れ、E列の表示形式を `+0.00;-0.00;0.00` にする。
- 測点別に明細をまとめる。最終明細の次の行でA〜Cを結合して「測点別集計」とし、D〜Gに「測点、最大絶対差 (mm)、レンジ (mm)、再確認」を置く。小見出しは `K Summary Header`（青緑地、10pt白太字、左寄せ、折返し）を指定し、行高は25ptを目安に文字が収まる高さにする。
- 測点ごとの比較差の範囲に対し、E列には `=MAX(ABS(MIN(範囲)),ABS(MAX(範囲)))`、F列には `=MAX(範囲)-MIN(範囲)` を入れる。両列の集計セルに `K Total Dimension` を適用し、右寄せで常に小数第2位まで表示する。D列の測点ラベルは `K Text`、G列の確認内容は `K Text Indented`。集計値の行は22ptを目安にし、原稿の再確認目安を次の行のA〜Gを結合して `K Note` で入れる。集計と注記も印刷範囲に含める。
- 印刷プレビューで小見出しから最後の集計値・注記までを確認する。途中で改ページする場合は、最終明細行の直後に手動改ページを入れる（`from openpyxl.worksheet.pagebreak import Break`、`ws.row_breaks.append(Break(id=最終明細行))`）。手動改ページを使うときは `ws.sheet_properties.pageSetUpPr.fitToPage = False` とし、`ws.page_setup.scale = 90` を出発点にA〜Gが横1ページに収まる倍率を選ぶ。1〜6行の繰返しは維持する。15明細・明細行高32ptの見本では21行目の直後に改ページし、次のページに小見出し・集計値・注記を置く。集計ブロックが1ページより長い場合は、集計値の行を区切り、続くページの先頭に同じ小見出しを置く。
- `bin/recalc` の後、1ページの見本と明細・集計が改ページする見本を `bin/render` に通す。全ページで文書番号の末尾、日付、作成者、数値と隣接文字の間隔を点検する。集計小見出しと対応する値が同じページにあり、Cの最大絶対差 `0.04` とレンジ `0.01` が正しい見出しの下に並ぶことを確認する。

## 型を使わないもの

不良履歴のCSVは抽出元の表記と履歴番号を保ち、パレート図PNGは分類済み件数を降順に並べ、件数・累積比率の軸と母数を示す。装置CSVは素の測定出力、EMLは送受信ヘッダ・本文・必要な添付を持つメール、TXTは中山の作業メモ。写真はPicturesの現物・測定箇所、管理図PNGは実測値から描く図であり、Officeの用紙枠を付けない。管理限界と仕様限界を混同せず、単位・対象期間・サンプル定義を原稿どおり示す。写真・手書き制作時にはimagegen skillを読む。本工程では写真や手書きの代用品を作っていない。

## 見本の確認

見本は各実行の作業フォルダに作り、`bin/render` で全ページを確認する。校正結果・ロット再評価表は両シートに文書番号、版、基準日、作成者、確認者、照合範囲を入れる。短い明細の見本と、器別・ロット別の両方で改ページする見本を使い、管理欄と列見出しの繰返し、右寄せ数値と隣接文字の間隔、保留数の表示を確かめる。英文証明は証明書番号・発行日・校正日・発行者と実際に桁が入った数値表を見本に入れ、PDFと紙受領分のスキャンで読めることを確かめる。
