# 山田美由紀の文書の型

中京文書配送サービス株式会社の情報管理統制と、さくら情報管理審査合同会社、日高文書保管株式会社、三和オフィス機器株式会社から受け取る文書の型。Officeの型は通常のDOCX・XLSX・PPTXであり、開いて別名保存する。本文の事例・仮の値・空の明細・仮の集計は持たない。

## 組織の識別と書式

- 中京のロゴは赤茶の封筒の輪郭と折り目、その手前を右へ進む砂色の配送矢印、会社名の文字。主色 `8C3B2F`、本文の墨色 `333C43`、補助の砂色 `A99474`。白地で、集計の淡い背景 `EFE9E1` は補助色の濃淡とする。210人の配送会社の審査窓口として小型の社名ロゴと簡潔な業務用紙にし、装飾表紙は設けない。
- Officeの日本語・欧文は Noto Sans CJK JP。TeXの日本語も同じ、欧文は環境にある Liberation Sans。Word・Excel・PowerPointはロゴ画像を内部に埋め込み、TeXは同じ封筒・折り目・矢印を図形で組む。外部画像ファイルへの依存はない。
- さくらは5つの円形の花弁と白い花心、審査機関の社名。紅紫 `9A647C` と墨色 `333C43`。日本語・欧文とも Noto Serif CJK JP。見出し、表の見出し、ヘッダ罫線も紅紫。社内の赤茶・ゴシック・封筒と区別する。社外から届く依頼リストはこのWordに表として入れ、社内の提出一覧は中京のExcelを使う。
- 日高は横棚と3区画を表す線画と社名の文字。濃い青緑 `195B5B` をロゴ・題・見出し・横罫線・点検表に使い、本文と管理欄は墨色 `242E30`。日本語は Noto Serif CJK JP、欧文は Liberation Serif。ヘッダ右に「保管管理」、フッタに社名と現在頁／総頁を置く。発行番号は `HD-HK-YYYYMM-連番`（発行月、月内2桁）、版は別欄。管理欄は発行日と作成者を載せ、点検実施日は本文で示す。
- 中京の文書番号は `CD-IM-YYYYMM-用途-連番`。用途は `ANS`（回答）、`COR`（是正記録）、`MTG`（読み合わせ）、`IDX`（証跡・提出一覧）、`CHK`（点検）、`BRF`（説明）。さくらの発信番号は `SK-YYYY-用途-連番`、用途は `REQ`（依頼）・`OBS`（所見）。番号を付ける文書だけに計画で割り当てる。改版・DOCXから保存するPDFは同番号で版を分ける。是正案件番号と文書番号は別項目として管理する。型にダミーの番号は入っていない。
- Wordは社名ヘッダと組織・用途・ページ番号のフッタ。Excelは上段に社名と題、印刷フッタに情報管理統制とページ番号。PowerPointはマスターに社名ロゴ・上罫線・情報管理統制を持つ。TeXは社名ヘッダ・情報管理統制・現在頁／総頁。
- 他personaのREADMEと、p14の `cedar-review.docx`、p05の `oriba-analysis.docx` の実物の書体・見出し色・ヘッダとロゴを開いて比較した。深緑の角材、藍の織り目、p17の柱梁、p18の寸法枠、p12の枝と灯とは、封筒と配送矢印・赤茶の組合せで分けた。他personaは変更しない。

## Wordの使い方

`Document(型)`で開き、用途に応じて見出しの下へ原稿の本文を挿入する。最初の見出しの前にTitleの実題と `CD Metadata` の文書番号・版・作成日・作成者・確認／承認者・宛先を原稿に従って入れる。草稿の承認欄に未来の承認を入れない。不要な見出しは削り、空の節を完成文書へ残さない。独立した表紙は作らない。

- A4縦、左右22mm、上29mm、下22mm。`Normal` 10.5pt、段落後6pt、行間1.18。`Title` 23pt、`Heading 1` 13pt、`Heading 2` 11pt、いずれも組織の主色と太字。`CD Metadata`、`CD Note`、`Caption`は9pt。
- 表は必要な内容があるときだけ追加し、テーブルスタイル `CD Table` を指定。先頭行の段落は `CD Table Header`（白字・太字9pt）、本文セルは `CD Table Body`（墨色9pt）。先頭行の塗りと罫線はテーブルスタイルに定義済み。先頭行の `trPr` に `w:tblHeader` を追加し複数頁で繰り返す。
- 列幅・行高は実際の文面に合わせ、長い根拠は本文へ分ける。本文用のNormalを白抜き見出しセルにそのまま使わない。社外型でもスタイル名は同じで、書体と主色はさくら用に実装している。
- 回答のPDFは `chukyo-response.docx` に内容を入れて `bin/office-pdf` で保存する。山田から池田へ提示する英文要約も中京の回答型を開き、題・見出し・管理欄・本文を英文にする。フッタの組織・用途の文字列を英語に差し替え、ページ番号フィールドと社名ロゴを維持する。池田が発行する審査依頼・講評のPDFは内容を入れたさくらのWordから保存する。

## Excelの明細と集計を作る方法

`load_workbook(型)`で開く。1行目は埋込みロゴ、2行目は題、3〜4行目は管理項目、6行目は列見出し。5行目は未書式の余白。7行目以降には空の書式行・仮の合計・数式を置いていない。入力欄とブックの既定書体も Noto Sans CJK JP。

1. B3:D3の結合セルに文書番号、F3に版、H3に基準日、B4:D4に作成者、F4:H4に確認者を設定する。3行目は30pt、4行目は25pt、入力欄は9ptで折返す。H3は実日付と `yyyy-mm-dd` を設定する。2行目の題・シート名・6行目の列名と列幅は原稿に合わせる。提出一覧へ使う場合は、依頼番号・資料名・版・提出日・宛先・保存先など必要な列へ変更する。
2. 実際の明細だけ7行目から作る。セルを作ったあとに名前付き書式を指定する。文字は `CD Text`（10pt）、整数・数式は `CD Number`（10pt、右寄せ）、日付は `CD Date`（実日付、`yyyy-mm-dd`）、注記は `CD Note`（9pt）。全て上揃え・折返し。`CD Text`・`CD Date`・`CD Note` は左寄せ、左インデント1。先頭の連番や照合件数と右隣の値の間に余白を取る。行や列を組み替えてもインデントを維持し、折返しが増える場合は列幅と行高を調整する。整数の書式は `#,##0;[Red](#,##0);0`。識別番号は文字列として保存する。欠落した承認日は空欄のままにし、状態列と注記で欠落・未確認を区別する。
3. 集計に意味がある表だけ、最終明細の次へ実際の集計行を作り、ラベルと数式のセルへ `CD Total` を付ける。淡い砂色背景、太字、二重下罫線。ラベルの配置をコピーして `horizontal="left"`、`indent=1` に設定し、数値は右寄せ。実範囲を指す `COUNTA`・`COUNTIF`・`SUM` 等を原稿に従って入れる。証跡件数、欠落件数、是正判定の件数はそれぞれ対応する範囲から集計する。
4. 注記がある場合だけ `CD Note` の行を追加する。短い明細の見本は30ptだが、長い保存先・根拠に応じて高さを増やす。内容を隠す固定行高や過度の縮小は避ける。A4横、幅1頁・縦自動、1〜6行目の繰返し、C7固定を維持する。`print_area`をA1から実際の最終行・列まで、`auto_filter.ref`を6行目から最終明細までに設定し、合計と注記をフィルタから外す。列構成を変えた場合は管理欄と結合範囲も揃える。印刷プレビューで合計と注記だけが続頁に出た場合は、最終明細の一部と合計が同じ頁に収まるよう改頁位置を調整する。
5. 数式結果は `bin/recalc` と画像で確認する。CSVにはロゴ・管理行・書式を持ち込まず、原稿の列と明細だけを出す。XLSXと同じ版の一覧をCSVにする場合は、対象件数・識別番号・承認日の空欄・日付を一致させる。

RISK-031の評価表には `chukyo-checklist.xlsx` を使い、例えば「対象番号／未実施の内容／影響・判断根拠／担当／証拠回収期限／受容判断／必要な是正／確認者」とする。受領証拠の対応表には `chukyo-evidence.xlsx` を使い、例えば「対象番号／資料名／提供者／受領日／実施日／記録の所在／是正判定／判定根拠・不足」とする。対象番号で両表を照合し、資料の受領日と点検の実施日を別々に記入する。署名済み点検票から根拠の所在へたどれるようにし、継続行には不足している記録を明記する。

## 三和から届いた質問票の作り方

三和の主色は紺 `283F65`、本文は濃い青灰 `253248`、質問欄は薄青 `F1F5FA`。ブックの既定書式 Normal、管理欄、列見出しと明細は和文・欧文とも Noto Sans CJK JP。フッタは左に社名・購買課、右に現在頁／総頁を置く。

1. `load_workbook("sanwa-assurance.xlsx")` で開く。B3:C3に質問票番号（`SW-PQ-YYYY-MM`、2025年2月号は `SW-PQ-2025-02`）、E3:G3に版と発行日、B4:C4に回答先の部署と担当者、E4:G4に回答期限を入れる。結合セルの左端に値を書き、28ptの行高と折返しを維持する。期限は実日付と `yyyy-mm-dd` で保存し、ブックの作成者には発行担当者を設定する。
2. 6行目は質問番号・区分・確認事項・回答区分・回答・確認時点・補足。7行目から原稿の設問がある行だけを作る。A〜C列の文字には `Sanwa Question`（左寄せ・インデント1）、実際の整数には `Sanwa Number`（右寄せ・インデント1、`#,##0`）を指定する。Q01のような質問番号は文字として保存する。D〜G列は `Sanwa Reply`（白地、左寄せ・インデント1）を付け、受領時は空欄にする。受領票の明細の末尾には集計行を設けない。中京の回答明細は中京の点検表型で別に作る。
3. 明細の行高を30ptから始め、区分や確認事項の折返しに合わせて広げる。数値の右隣に文字が来る列でもインデントを保つ。印刷範囲をA1:G最終行、フィルタをA6:G最終行に設定する。A4横、幅1頁・縦自動、D7の固定、印刷時の1〜6行の繰返しとページ番号を維持する。

## PowerPointの使い方

`Presentation(型)`を開き、実レイアウト `slide_layouts[0..4]` を使う。順に「表紙」「見出しと本文」「2段」「表」「図」。共通の社名ロゴと罫線・部門表記はマスター上にあり、本文は入っていない。

- 題はidx=0。本文・副題・表・画像の領域はidx=1、2段の右はidx=2。表紙の題32pt・副題18pt、その他の題28pt・本文20ptを継承する。表紙の副題に番号・版・日付・作成者を原稿どおり入れる。
- 表は `placeholders[1].insert_table(行数,列数)` で作り、赤茶白字の見出しと墨色の本文にする。値は18pt以上を目安に収める。図は画像プレースホルダへ `insert_picture` で入れるか、その領域（左0.6・上2.0・幅12.1・高さ4.7inch）に実際の図形を配置し、不要になったプレースホルダを削除する。縦横比を保ち、範囲からはみ出さない。
- 実ページ番号は各スライド右下の左12.1・上7.05・幅0.65・高さ0.3inchに10ptで成形時に追加する。発表者メモは原稿にあるときだけ格納する。型のレイアウト名や見本の文章を発表用の本文にしない。

## TeXと紙の記録

`TEXINPUTS="$PWD/templates/p03-security-grc-analyst:" bin/tex <当該workの原稿.tex> <当該workの出力.pdf>` で組む。`\documentclass{chukyo-paper-check}` を使う。

- `\CheckHeading{題}{文書番号}{版}{点検日}{記録者}`、`\CheckSection{見出し}`、`\CheckNote{注記}`、`ApprovalTable`環境、`\CheckSignatures{点検者}{確認者}` を用意している。
- 表は証跡番号・点検項目・照合した記録・結果・確認者の5列。本文幅166mmの内側に収まり、見出しは続頁に繰り返す。原稿にある行だけ `番号&項目&根拠&結果&確認者\\\hline` で追加する。型の中に空の記入行・架空の印・署名はない。署名の名前欄もマクロを呼んだときだけ作る。
- 署名付き紙の点検票は、中身のある原紙を先に組み、手書きの署名・筆記が必要な段階でimagegen skillを読んで素材を作る。活字の氏名を手書き署名の代わりにしない。内容と署名を備えた紙面を `bin/scan` に通し、画像だけのPDFを作る。本段階のTeX見本は組版確認用で、署名済みスキャンではない。

## 型を通さないもの

メールはEML、山田の作業中のメモはTXT・Markdown、証跡一覧のデータ交換はCSVとし、ロゴや一律の文書番号を付けない。リスク図は実際の評価と判定の時点が伝わるPNGにし、図に記す件数・判断を評価表と揃える。証跡画面は業務画面として作り、画面の日時・承認日・件数を原稿の時点と一致させる。

## 日高文書保管の契約継続判断（2024年）

- 山田の受領資料と有効期間の対照表には `chukyo-evidence.xlsx` を使う。6行目を「No.／資料名／版・発行番号／受領日／有効開始／有効終了／照合状態／根拠・次の確認」にし、列幅の目安を順に 7・29・22・14・14・14・15・30 とする。No.は `CD Number`、資料名と発行番号は `CD Text`、受領日と有効期間は `CD Date`。資料に有効期間の記載がない場合は該当日付を空欄にし、根拠欄にその旨を記す。点検の実施日・発行日・受領日は原記録で区分する。
- 井上への条件と確認事項は `chukyo-response.docx` の見出しを「対象と判断／照合した根拠／継続条件／担当と次の確認」に差し替えて書く。管理会議の要点は `chukyo-control.pptx`。8月26日の提出12資料・更新待ち3件による保留と、9月20日の訂正根拠の照合・佐々木の条件付き継続を経過順に扱う。購買台帳の抽出CSVと照会EMLは元の形式で作り、2025年のRISK-031とは別の案件として管理する。
