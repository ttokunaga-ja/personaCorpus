# 坂本修一郎の文書の型

対象は汐葛休憩棟改修の自主点検、完成検査、是正、仮使用条件、引渡し（2025年9月8日〜30日）。普通のDOCX・XLSX・PPTXを開き、別名で保存して使う。型は組織の識別、固定の文書種別、スタイル、列見出しだけを持つ。案件の事実・文書番号・是正内容は計画と原稿から入れる。

## 組織の識別と文書番号

湊梁建設のロゴは2本の柱と水平の梁、その上の橙の細線、社名文字の組合せ。OfficeのWord・Excelは図形を画像として埋め込み、PowerPointとTeXは同じ構成を図形で持つ。色は青灰 `263D4A`、橙 `CE702B`、本文の墨 `30383C`。橙は罫線や小さな強調に限り、記録の本文は墨で読みやすくする。中規模の施工会社の現場書類として、装飾的な表紙や大きな余白は足さない。日本語・欧文ともOfficeでは Noto Sans CJK JP。TeXの日本語は同じフォント、欧文は Liberation Sans。ヘッダはロゴと社名、フッタは湊梁建設株式会社・工事部とページ番号。Excelには組織名を上段、ページ番号を印刷フッタに持たせる。

自社番号の書式は `MB-SK-YYYY-用途-連番`。用途は検査 `IN`、日報 `DR`、使用条件 `UC`、送付 `HO`、指摘台帳 `PL`、書類一覧 `DX`、説明 `BR` とする。検査票も `IN` を使う。年は文書の年、連番は用途内で付す。実際の番号は計画・事実台帳で定め、型には埋め込まない。同じ文書のWordとPDFは同じ番号、改訂は版で区別する。写真や個人メモにはこの番号を強制しない。

汐葛食品はえんじ `814454` と墨 `30383C`、日本語・欧文とも Noto Serif CJK JP。円で囲んだ菱形と社名を使い、施工会社とはフォント・色・ロゴを変える。フッタは汐葛食品株式会社・工場管理とページ番号。施主の番号は `SK-KK-YYYY-連番`、版は別に記録する。型に担当者の署名、押印、所在地、電話番号、実在の会社の識別情報は入れていない。

他personaで既存の `templates/p14-finance-controller/` のREADMEとWord・Excel・PowerPointの実物を開いて比較した。Cedar Worksの深緑と木材の階段状ロゴ、親会社の青、銀行の明朝・えんじに対して、湊梁建設は青灰・橙と柱梁のロゴを採用。汐葛食品の円・菱形ロゴも銀行の山形ロゴとは異なる。

## Wordの使い方

- 本文は `Normal` 10.5pt、`Title` 21pt、`Heading 1` 13pt、`Heading 2` 11pt、`Caption` と `Site Note` は8.5pt。自社はゴシック、施主は明朝。段落後7pt、行間1.18。A4、左右21mm、上29mm、下22mm。全種類とも独立の表紙は作らない。
- 固定の文書種別の題の後に、原稿の工事名、宛先、文書番号、版、文書日、作成・確認者を `Site Metadata` 9ptで追加する。個々の見出し・本文は原稿から追加する。型に空の記入表や仮の署名欄はない。
- 表を追加する場合は `Site Table` を指定。先頭行を見出しにし、`w:tblHeader` を付けて次ページでも繰り返す。表の見た目の設定で「最初の行」を有効にし、ヘッダセルに `Site Table Header`（白字太字9pt）、明細セルに `Site Table Body`（墨9pt）を指定する。自社は青灰、施主はえんじの見出し背景。罫線は灰色。実際の明細だけを挿入し、行高は固定しない。数値は右寄せ、文章は左寄せとする。
- 写真は幅168mm以内、縦横比を維持して配置し、Captionに通り芯・撮影日・是正前後・写真参照を原稿どおり記す。大きい写真は改ページし、キャプションとの分離を避ける。写真自体はPicturesの原本と対応させる。
- 仮使用条件では使用範囲、立入を分ける箇所、残る是正、担当・期限、施主確認を混同しない。型は条件の内容や11件の内訳を決めない。引渡し書類は太田の照合記録と対応させ、受領側の記録は施主の型で作る。

## Excel の行を作る方法

両型には1行目のロゴ・社名、2〜3行目の管理ラベル、4行目の列見出しだけがある。明細行、合計行、仮の式、空の罫線行はない。書式はブックのNamedStyleとして保持する。既定セル書式とNamedStyleのNormalはいずれもNoto Sans CJK JP・10pt、墨 `30383C`、左寄せ・左インデント1で、テーマフォントに依存しない。管理項目の空の入力先にも同フォントを実際に指定してある。

1. `load_workbook(型)` で開く。管理欄はA2=文書番号、B2:C2=番号入力先、D2=版、E2=版入力先、F2=基準日、G2=日付入力先。3行目はA3=工事名、B3:C3=工事名入力先、D3=作成者、E3=氏名入力先、F3=確認者、G3=氏名入力先。結合セルには左上のB2・B3へ値を入れる。管理欄は10pt、左インデント1・縦中央、折返しなし・縮小なし、2〜3行目の高さ26pt。G2には実日付を入れ、型の `yyyy-mm-dd` を維持する。管理欄に明細用スタイルを上書きしない。`MB-SK-2025-PL-002`／`MB-SK-2025-DX-001` の全文が1行で印刷される。
2. 初期列幅は指摘台帳がA=12、B=22、C=48、D=15、E=14、F=14、G=36、書類照合表がA=16、B=37、C=26、D=14、E=15、F=15、G=38。番号欄B2:C2の合計幅はそれぞれ70・63文字幅。列を足す・並べ替える・狭める場合もB2:C2・B3:C3の結合を維持し、Aは12以上、B+Cは44以上、D〜Fは14以上、Gは22以上を目安にする。文書番号・版・日付・工事名・両氏名をすべて実際の長さで埋め、少数行と複数ページの全ページで表示を確認する。番号が長くなれば結合幅を広げ、ラベルと入力先も必要に応じて移す。折返しや縮小で対応しない。
3. 原稿の実明細を5行目以降に作る。文字は `MB Text`、整数・件数・先頭の番号は `MB Number`、日付は `MB Date`、注記は `MB Note`。Noto Sans CJK JP、本文10pt・注記9pt、上揃え・折返し。文章は左寄せ・左インデント1、数値は右寄せ・インデント0、日付は中央・インデント0。整数は `#,##0;[Red](#,##0);"—"`、日付は `yyyy-mm-dd`。`MB Text` と `MB Note` は型のNamedStyleに左インデント1を設定済み。数値列の右隣に文字列が来るときも、先頭番号列の右隣も、この余白を維持する。列を追加・並べ替えるとき、または配置を上書きするときも文字セルには `Alignment(horizontal="left", vertical="top", wrap_text=True, indent=1)` を指定する。文字幅にインデント分を加えて列幅を確保し、数値と文字が接していないことを印刷画像で確認する。未是正・未確認をゼロや架空の日付で埋めず、状態と期限を区別する。
4. 集計が原稿に必要な場合だけ、最終明細の次に合計・件数行を作る。ラベルと実数式のセルへ `MB Total` を適用する（青灰の太字、淡灰背景、二重下罫線）。ラベルは左寄せ・インデント1へ変更し、数式は右寄せ・インデント0。指摘番号がすべて入っている場合の件数は `COUNTA(A5:A最終明細行)`、完了数は実際の状態列の値を参照する。書類照合表に意味のない合計は追加しない。数式は成形後に `bin/recalc` で結果を確認する。
5. 行高は実文量に応じて設定する。短い明細の目安は30〜42pt、長い文章にはさらに高さを確保する。見出し行も左インデント1を維持する。列を変える場合は見出し・幅・印刷範囲も実内容に合わせる。用意した7列ではC5で固定し、A4横、幅1ページ・高さ自動、1〜4行を各ページに繰り返す。印刷範囲を `A1:G最終内容行`、オートフィルタを4行目から最終明細行まで設定する。列を足した場合は1行目の社名結合をB1から最終列まで広げ、印刷範囲とフィルタの末尾も最終列へ広げる。合計行はフィルタ対象に含めない。長い明細行がページをまたがないよう、実文量と倍率に応じて `ws.row_breaks.append(Break(id=改ページ直前行))`（`openpyxl.worksheet.pagebreak.Break`）を設定する。今回の42pt・38行見本では10明細ごと（14・24・34行の後）に改ページする。印刷倍率で文字が小さくなる場合は内容を分ける。

## PowerPointの使い方

`Presentation(型)` を開き、`slide_layouts[0..4]` の表紙・見出しと本文・2段・表・図から選ぶ。すべて実レイアウトで、見た目だけを空スライドにコピーしたものではない。プレースホルダのidxは題0、本文または表・図の領域1、2段の右2。表紙題32pt、その他の題28pt、本文19〜20ptが初期値。日本語はNoto Sans CJK JPで、テーマの欧文・東アジア書体も同じ指定にしてある。

表・図レイアウトの領域1は汎用オブジェクトのプレースホルダ。表や図形、画像をその座標・寸法以内に追加して置き換え、元の領域は削除する。表の見出しは青灰白字、本文は墨、最小18ptを目安とし、多すぎる行は分割する。図は縦横比を守り、通り芯や凡例を付ける。表紙の副題には原稿の文書番号・版・日付・発表者を入れ、各スライド右下には実際のページ番号を追加する。共通のロゴ・社名・罫線・部門表記はマスターから継承する。発表者ノートは原稿にある場合だけ追加する。

## TeXの使い方とスキャン

`TEXINPUTS="$PWD/templates/p17-construction-project-manager:"` を渡し、当該batchのscratchに置いた `.tex` を `bin/tex <入力.tex> <出力.pdf>` で組む。

- `\documentclass{minatoryo-field-sheet}`、`\SiteHeading{題}{文書番号}{工事名}{実施日}{記録者}` で開始する。
- `\SiteSection{見出し}`、`\SiteNote{注記}` は内容がある場合だけ使う。
- `FieldTable` 環境の各行に、番号、位置（通り芯）、点検・指摘内容、対応・確認根拠、確認者の5項目を `&` で区切って入れる。行末は `\\\hline`。環境側に列見出しと繰返し設定があり、原稿の明細だけを追加する。本文幅168mmの内側に収まる列幅を設定済み。長い記録は明細単位で改ページする。
- 型の中には仮の点検内容・空の記入行・署名欄を配置していない。印刷した検査票へ現場で筆記した記録を作る際は、原稿の内容を持つ原紙を先に組み、筆記そのものはimagegen skillを読んで作る。活字の見本を手書き記録の代わりにしない。最終的な内容入り画像またはPDFを `bin/scan` に通す。
- Word・Excel・PowerPointから保存するPDFはOffice経由とする。是正確認・受領の施主PDFは施主のWordを使い、TeXの施工側ロゴを付けない。

## 型を使わない記録

坂本の作業中のメモ、メール、CSV、現場写真にはロゴや文書番号を一律に付けない。写真はPicturesに撮影日で整理し、位置は実在住所でなく通り芯で示す。写真・手書きの画像を制作する段階ではimagegen skillを使う。本作業の図版見本は配置確認の幾何図形であり、現場写真でも手書き画像でもない。

## 汐葛の完成検査で用いる型なしの記録

- `text`：坂本のTXT覚書と保存したEML。ロゴ・文書番号を付けない。EMLは差出人・宛先・送受信時刻と返信関係を本文と一致させる。
- `photo`：Pictures/汐葛休憩棟改修/撮影日/の指摘・是正写真。型なし。同じ指摘の前後は通り芯・背景・向きをそろえ、原稿に小黒板の文字と写る対象を指定する。
- `handwriting`：坂本の検査手帳。型なしの手書き記録で、成果物の作り方は `scan:handwriting`。原稿に全頁の筆記内容を指定し、成形時にimagegen skillを読んで画像化した後bin/scanでPDF化する。検査終了時点の記録に後の是正結果を先取りしない。
- 施主の書類受領控えは `scan:office:shiokuzu-confirmation.docx`。内容を入れた施主の原紙に手書きの受領者名・照合印を加え、bin/scanに通す。型自体に署名を足さず、Office原紙と手書き素材は当該実行のwork内に置く。

今回の計画に新しいOffice・TeXの型は不要。PDFだけを保管する引継ぎ案内・施主確認書は既存の各型から作り、配布物に不要な元Wordを増やさない。

### 追加Office型の使い方

- Wordの変更説明は既存の自社Wordと同じNormal・Title・Heading 1/2・Site Metadata・Site Table系スタイルを使う。タイトルの後に案件・相手・番号・版・日付・作成者を足す。履歴付き版はw:ins/w:delとコメントで人物・日時を保持する。PDFだけの提出控えはwork内の中間Wordからbin/office-pdfで出し、不要なWordをpeopleに増やさない。
- 海田流通の承認控えは海田の型に原田の全文を入れる。工事名・図番/版・見積番号/版・税区分・金額・追加作業日数・対象外の最終工程調整・承認者/日付を実際の文書に合わせて足し、原紙はwork内に置く。本文の承認者名で発行する控えで、手書き署名や押印の画像を一律に作らない。
- 追加Excelも引渡し書類照合表と同じ4行だけの骨組みとNamedStyle（MB Text/Number/Date/Total/Note）を持つ。管理欄・ロゴ・フッタ、明細のインデント、実行数に応じた行追加、全印刷範囲と反復見出しの方法は上の「Excelの行を作る方法」に従う。コピーシートにも管理欄と印刷フッタを継承する。
- 数量型の明細はC列数量、D列単位、E列単価、F列金額、G列根拠を基本とする。単価・金額は円で計算し、万円表記は文書中の説明でのみ換算する。数量・単価・金額はMB Numberで右寄せ、小数の桁は単位に合わせる。合計・控除・消費税は原稿の実際の位置に数式とMB Totalの行を作り、型に仮の合計を残さない。数量だけの表は列名を原稿に合わせて変更してよいが未使用の金額欄は残さない。
- 工程型はC・D列を実日付とMB Date、E列を稼働日数にする。WORKDAYで土日を除く日付を求め、日付軸・横棒・凡例は原稿の全データから作る。作業日の並びと引渡し予定の差を分け、複数シートの印刷範囲に基準日・条件・未確定の注記まで入れる。
- 既存の `minatoryo-site-brief.pptx` は自社の共通マスターと5レイアウトを持つため、海田西配送棟の工程説明にも使える。検査や引渡し済みの文言は固定されていない。各枚は原稿から作り、図・表と発表者ノートを省略しない。
- 海田西配送棟の自社番号は `MB-KN-YYYY-用途-連番` とする。用途はQT（数量）、CO（変更見積）、SC（工程）、BR（説明）、MT（協議）。海田流通の承認は `KR-YYYY-連番`、白島設計室は図番D-41/D-42と改訂記号、質疑はRFI番号で管理する。実際の番号・版はfacts.mdと原稿に持ち、型に固定しない。

### 設計図枠と型なし記録

- `tex:hakushima-drainage.cls`：work内のTeXから読み込む。`\DrawingHeading{題}{工事名}{図番・版}{日付}{作成者}{状態・縮尺}` と `\DrawingSection{見出し}` を使う。図はTikZで通り芯、寸法線、流向、桝、管底、旧新の凡例を実際に描き、文章だけで図面の代用にしない。RFI回答は同じ図枠で本文・比較表を組む。クラスの探索先にtemplatesの絶対パスを加えてbin/texを使う。
- `text`：海田流通・白島設計室とのEMLと坂本の私的TXT。型なし。実添付と返信引用の対象は計画の「先に要るもの」に従う。
- `photo`：海田西配送棟の現況・干渉・作業面写真。型なし。日時と通り芯、未施工/予定の別を原稿に明記し、成形時にimagegen skillを使う。
- `diagram`：排水経路比較と工程比較のPNG。型なしの坂本作成の説明図。本文の値と位置から描き、軸・単位・凡例を付ける。
- `scan:handwriting`：型なしの現地採寸手帳。原稿に全頁の略図・寸法・筆記を指定し、imagegen skillで画像化後bin/scanに通す。
- `scan:office:minatoryo-change-note.docx`：説明案の印刷物への赤字。元Wordをレンダリングした用紙を変えず、手書きをimagegenで加える。
- `scan:office:minatoryo-change-schedule.xlsx`：印刷工程表への協議時の赤字。計画の元PDFをderived_fromとし、印刷済みの旧日付・版は保持して手書きだけを加えbin/scanに通す。
