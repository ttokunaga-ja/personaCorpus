# 上田由美香の文書の型

灯枝サービスの支援文書と、白樺ビルメンテナンス・露原機材販売・円山印章から届く表の型。通常の DOCX・XLSX・PPTX を開き、別名保存して使う。型は見出し・組織表示・書式だけを持ち、事例本文、仮の値、空の明細行、仮の集計欄は持たない。

## 灯枝サービスの共通書式

- ロゴは紫の幹から斜めに伸びる枝と、枝先の琥珀色の円（灯）、社名の文字。主色は紫 `514369`、補助は琥珀 `CC963F`、本文は墨 `33313A`。白と淡紫 `F0EDF4` は背景。Word・Excelではこの図形と社名を画像として内部に埋め込み、PowerPointとTeXでは図形で描く。外部画像へのリンクはない。
- 日本語は Noto Sans CJK JP。Officeは欧文も同じフォント。TeXの欧文は環境にある Liberation Sans。122人規模のサービス会社の読みやすい小型ロゴと余白にし、大きな装飾表紙は作らない。
- 文書番号は `TS-CS-YYYYMM-用途-連番`。用途は `ESC`（調査・開発照会）、`HND`（引継ぎ）、`ANS`（顧客案内）、`TRI`（切り分け）、`QUE`（未解決）、`BRF`（共有スライド）、`REC`（記録出力）、`QBR`（顧客会議の論点案と議事録）、`QLT`（支援品質報告）。実際に番号を付ける文書だけ、計画・台帳に沿って設定する。草稿・送付版・PDFは同じ番号で版を区別する。型にダミー番号は焼き込まない。システムの相談番号は文書番号とは別の項目。
- ヘッダは社名と用途、フッタは組織・部門とページ番号。Excelは上部の組織画像とシート名、下部の組織名とページ番号。PPTXは上部の社名と下部の部門名をマスターで継承し、スライド番号は成形時に追加する。

## Word

`Document(型のパス)` で開く。本文は用途別の見出しだけで、空の表や記入を促す仮文はない。先頭の見出しより前へ `Title` の題と `TS Metadata` の文書番号・版・日付・作成者を追加する。顧客向けは原稿に従って宛名と発信者も記載する。見出しは必要なものだけ使用し、空の節を成果物に残さない。

- A4縦、左右23mm、上27mm、下22mm、表紙なし。
- `Normal` 10.5pt、`Title` 22pt太字、`Heading 1` 13pt太字、`Heading 2` 11pt太字。段落後7pt、行間1.18。`TS Metadata`・`TS Note`・`Caption` は9pt。
- 表を追加するときは `TS Table` を指定する。先頭行の段落を `TS Table Header`（9pt太字・白）、本文セルを `TS Table Body`（9pt）にする。見出し行の繰返しは `w:tblHeader` を付ける。先頭行の紫塗りはテーブルスタイルが持つ。長い根拠は本文へ出し、列幅と折返しを内容に合わせて調整する。
- メール本文はWordから自動転載しない。原稿の草稿と実際に送った内容をそれぞれ保存する。作業中の個人メモまで会社の文書書式にしない。
- 顧客会議の型は開催概要に日時・出席者を置き、議題ごとの結論を見出しで分ける。「担当と次回確認」には原稿にある行動だけを表で記す。論点案に決定事項のない段階では該当見出しを削り、コメントを付けた版はWordのコメント機能を使う。
- ナレッジの改訂原稿は顧客案内の型を開き、原稿に合わせて「対象の作業」「適用条件」「操作手順」「操作後に確かめること」などに見出しを差し替える。指摘入りの版では、該当箇所を選択してWordのコメントを付け、実際の指摘者を設定する。コメント入りの原稿は社内で扱う。
- 調査中の定型返信の英文案は顧客案内の型を開き、ランの書式を保って用途ヘッダを `Customer update draft` に差し替える。本文は適用条件、確認できた事実、次回連絡、未確認事項のように原稿に沿って区切る。修正履歴を含む版はWordの変更履歴機能で、またはOOXMLの `w:del`・`w:ins` によって、該当する旧文と新文を記録する。各変更に固有のIDと実際の編集者・日時を付け、履歴表示で削除と挿入が読めることを確認する。
- 再研修の講評は当番引継ぎの型を開き、ロゴ下の用途表示を「管理者研修の講評」に差し替える。「実施概要」「分類課題の照合結果」「管理者への引渡し」「次の確認」を `Heading 1` で置く。照合結果には対象18人、初回と再試行の判定の根拠、分類誤り5人と1人を記す。2024年の初期研修で記録した宛先誤りは別項目とする。引渡しには残る1人が迷った操作と、石狩事務機側の管理者が個別支援で確かめる操作後の状態を記す。

## Excel の行を作る方法

`load_workbook(型のパス)` で開く。灯枝・露原の型は1行目に埋め込みの組織ロゴ、2行目に用途名、3行目に文書番号・版、4行目に基準日・作成者の管理欄、5行目に表の見出しを置く。6行目以降にはセルも数式も置いていない。明細は原稿にある行だけ追加する。白樺ビルメンテナンスと円山印章の型は下記の専用手順を使う。

1. B3:D3の結合セルに実際の文書番号、F3に版、B4に基準日、D4:F4の結合セルに作成者を設定する。ラベルはA3=文書番号、E3=版、A4=基準日、C4=作成者。入力先はすべて各社指定フォントの9pt・左寄せ・左インデント1・縦中央・折返しなし、3・4行目は各24pt。`TS-CS-202507-TRI-001`、`TS-CS-202507-QUE-001`、`TK-IMP-20250710-001` の全文を1行で印刷できる結合幅を維持する。列幅や列数を変更するときは管理欄の結合幅も確保し、番号・版・日付・作成者を同時に入れて印刷画像を確認する。番号を短縮したり縮小表示で収めたりしない。番号を付けない受領表ならB3は空でよい。シート名・2行目の題・列名と列幅は原稿に合わせる。顧客の添付が対象表とエラー表の別ファイルなら、使わないシートを削除してそれぞれ別名保存する。CSVには書式・ロゴ・管理ラベルを混入させない。
2. 灯枝は `TS Text`、`TS Number`、`TS Date`、`TS Note`、`TS Total`、露原は対応する `TH Text` 等の名前付きスタイルを使う。明細の各セルを作ってから割り当てる。本文10pt、注記9pt、全て折返し・上揃え。文字左寄せ・左インデント1、数値右寄せ。`Text`・`Date`・`Note` の名前付きスタイルに左インデント1を持たせてある。先頭の番号列の右隣も含め、数値の右隣に文字列・日付が来るときは、このインデントを維持して値を離す。列を追加・並べ替えするときも文字セルへ同じ名前付きスタイルを適用し、独自スタイルなら `Alignment(horizontal="left", vertical="top", wrap_text=True, indent=1)` と十分な列幅を設定する。右寄せの番号の隣に外部受付番号を置く場合も同じ。空白文字の追加で代用しない。整数は `#,##0;[Red](#,##0);0`、日付は実日付と `yyyy-mm-dd`。時刻も必要なら実値と `yyyy-mm-dd hh:mm` を指定する。番号や先頭ゼロを持つ値は文字列として扱う。
3. 合計が意味を持つ表だけ、最後の明細の次に行を追加し、ラベルと数式の実セルへ `TS Total` / `TH Total` を適用する。ラベルは左寄せ・左インデント1に上書きする。淡い背景・太字・二重下罫線を持つ。数える対象と重複除外を原稿に従って定め、実範囲への `COUNTA` / `COUNTIF` / `SUM` 等を使う。未確認をゼロとして足さない。相談件数と取込行数を混ぜない。仮のSUMや合計ラベルを追加しない。
4. 原稿の注記がある場合だけ末尾に `TS Note` / `TH Note` の行を追加する。注記の結合範囲は表の幅まで。長文は行高を増やし、必要ならページを分ける。見本の短い明細は34ptの行高で確認したが、実内容に合わせて調整する。
5. `auto_filter.ref` を見出しの5行目から最終明細まで、`print_area` をA1から実内容の最終行・列まで設定する。集計と注記はフィルタから除く。A4横、幅1ページ・高さ自動、1〜5行目を繰返し、C6で固定、左右0.3inch・上下0.35/0.4inchを維持する。文字が小さくなる場合は表の列を再構成する。数式結果は `bin/recalc` とレンダリングで確認する。

回避策の確認表では、取込切り分けの型を開き、シート名と2行目を「回避策の確認」に変更する。5行目に「照合順」「利用作業」「再現条件・試した操作」「確認結果」「確認者」「確認根拠・再確認先」を置き、AからFの列幅は順に12、18、32、16、14、32を目安とする。Aは `TS Number`、B〜Fは `TS Text` を使う。確認済みの根拠は操作後に観察した結果、未確認の根拠欄は試せなかった条件と再確認先を記す。件数を載せる場合はD列の該当状態を `COUNTIF` で集計する。

定型返信の採否表も取込切り分けの型を開き、シート名を「調査中の定型返信」、2行目の題を「調査中の定型返信の点検」にする。A〜Fの見出しは順に「No.」「旧文言」「誤読のおそれ」「採否」「採否の理由・訂正方針」「確認先」、列幅の目安は順に12、30、29、14、36、19。Aは `TS Number`、B〜Fは `TS Text` とし、明細行高49ptを目安に英文の長さに合わせる。B列の左インデント1を保つ。採否の理由には、旧文言が解決の確約と読める箇所と、確認済みの事実または次報に置き換える理由を記す。7件のみを明細に載せる場合はフィルタを `A5:F12` とし、注記を付ける場合だけ印刷範囲をA13の注記行まで広げる。

## TeX

`tomorie-export.cls` は Office を経ない印刷保存PDF用であり、画面のスクリーンショット用ではない。クラスを指定されたscratchのTeX原稿と同じディレクトリへコピーし、`\documentclass{tomorie-export}` として `bin/tex <原稿.tex> <出力.pdf>` で組む。型自体に本文や仮の表はない。

- `\TSRecord{題}{文書番号}{基準日}{出力日時}` で冒頭の管理情報を設定する。基準日と出力時刻はそれぞれ実際の記録に合わせる。作成者を載せる場合はその直後に `{\small 作成者：氏名}\par` を置く。
- フッタ左は `灯枝サービス株式会社 | サポート・サクセス`、右は自動ページ番号。問い合わせ記録という用途はヘッダ右に表示する。
- `\TSSection{見出し}` で紫の小見出し。本文10pt、余白22mm、上29mm、下23mm。ページ番号は自動。
- 表は `longtable` を使用し、先頭行に `\rowcolor{TSviolet}`、各見出しセルは `\textcolor{white}{見出し}`。繰返し見出しを `\endfirsthead` / `\endhead` で指定する。列幅の合計に列間余白を加えて本文幅166mm以内にする。数値列は右寄せにし、隣の文字列との間に列間余白を保つ。内容のない行は足さない。

`tomorie-guide.cls` を使う場合は、`tomorie-export.cls` もTeX原稿と同じディレクトリにコピーする。`\documentclass{tomorie-guide}`、`\TSGuide{題}{文書番号}{版}{公開日}{作成者}`、`\TSSection{見出し}` で組む。文書番号の用途は `ANS`。適用条件、操作順、操作後に確認する表示を原稿のまとまりで配置し、必要な図だけを `\includegraphics` で挿入する。

委託先への英文説明を組む場合は、`tomorie-partner-brief.cls` と継承元の `tomorie-guide.cls`、`tomorie-export.cls` をTeX原稿と同じディレクトリにコピーする。`\documentclass{tomorie-partner-brief}` と `\TSPartnerBrief{題}{文書番号}{版}{発行日}{作成者}` を指定し、直後に宛先、次いで `\TSSection{見出し}` で確認済みの事実と次回連絡を区切る。文書番号の用途は `ANS`。英字は Liberation Sans、日本語の社名ロゴは Noto Sans CJK JP。対照表は共通の `longtable` 書式を使い、見出しの紫と白字を設定する。

支援品質の分析報告は `tomorie-quality-report.cls` と `tomorie-export.cls` をTeX原稿と同じディレクトリにコピーする。`\documentclass{tomorie-quality-report}` と `\TSQualityReport{題}{文書番号}{版}{報告日}{作成者}` を使う。文書番号の用途は `QLT`。本文は `\TSSection` で照合範囲・判定根拠・集計・当番の申し合わせを区切る。内訳表には共通の `longtable` 書式を使用する。「26件のうち15件」という分母と判定を明示し、照合結果と切替え後の当番手順を分けて書く。

## 型を使わない記録

EMLは送受信ヘッダと本文・引用・必要な実添付を持つ保存メール。CSVは拠点の利用状況、既知問題の抽出、取込・エラー一覧などの素の表データ。TXT・MDは上田の作業中のメモ。PNGの操作図では操作前後で何が変わったか、HTMLの保存案内では利用条件・操作・結果が読めるようにする。研修ボードのJPGは研修の進行や現地の確認事項を撮った写真。問い合わせ管理画面の保存では、必要な対象行・状態・表示日時を残す。画面の製品名・エラー内容は計画と台帳に従う。
